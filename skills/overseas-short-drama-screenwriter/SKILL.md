# 海外高爽短剧完整剧本技能 2.3

## 一、核心目标

默认目标不是普通慢热连续剧，而是：

```text
目标国家
→ 本次实时市场研究
→ 找到当前观众欲望与情绪缺口
→ 原创高爽创意
→ 本地化
→ 人物与关系
→ 爽感引擎
→ 连载发动机
→ 全剧结构
→ 全集结构表
→ 逐集完整中文剧本
→ 连续性与爽点债务维护
→ 独立诊断与修订
→ 最终中文完整剧本
```

当用户要求完整剧本，最终必须写到：

```text
场次
+
动作
+
人物行为
+
完整对白
+
每集结尾
```

不能只交创意、梗概、分集简介。

---

# 二、最高优先级硬规则

## 1. 目标国家必须先确认

新建海外项目必须先知道：

```yaml
目标国家:
```

如果用户没有提供，先问：

> 这部短剧主要面向哪个国家或地区？

禁止默认美国，禁止把“海外、欧美、英文市场”自动当成美国。

多国项目必须指定一个主目标国家；主目标国家控制榜单研究、本地化和社会现实。

---

## 2. 最新市场必须本次实时检索

涉及“最新、当前、热门、榜单、排名、趋势、爆款、市场、下载、收入、现在流行什么、根据国外市场创作”时，必须本次实时外部检索。

模型训练知识只能用于编剧理论和历史背景，禁止作为当前市场证据。

没有实时证据时必须明确：

> 当前无法验证最新数据。

市场研究读取：

`references/market-research.md`

---

## 3. 所有给用户看的内容默认只用中文

默认：

```yaml
剧本输出语言: 简体中文
对白输出语言: 简体中文
```

包括市场分析、创意、人物、分集、场景、动作、对白、审稿和终稿。

海外本地化指故事逻辑符合目标国家，不等于必须输出外语。

只有用户明确要求外语版、中外文对照或海外发行文本时，才生成外语。

---

## 4. 默认创作模式是“高爽快节奏”，不是拖拉叙事

爽剧核心：

```text
快立痛点
→ 快让主角行动
→ 快给阶段回报
→ 对手有效反制
→ 主角升级
→ 更大兑现
```

强制读取：

`references/satisfaction-engine.md`

禁止：

- 主角连续多集只受辱不反击
- 同一误会靠“不说一句话”拖很多集
- 已有证据却故意不用来延长剧情
- 同一个秘密反复靠巧合打断揭露
- 每集只增加压迫却不给任何获得
- 反派只会辱骂，不会换策略
- 同一种打脸方式机械重复
- 靠随机新反派、新误会、新巧合续命
- 一集结束后人物处境、关系、信息、资源、目标全部没变

默认硬检查：

> 不允许连续两集都只有受压 / 铺垫 / 等待，而没有至少一种有效获得。

有效获得包括：证据、资源、关系优势、能力证明、真相推进、权力回收、反派受损、阶段爽点兑现。

---

## 5. 学习市场，不复制作品

允许学习：

- 题材
- 情绪承诺
- 人物原型
- 关系模式
- 爽感机制
- 钩子类型
- 连载发动机
- 节奏规律

禁止复制：

- 人物姓名
- 独特人物组合
- 标志性场景
- 台词
- 独特道具
- 完整节点顺序
- 特有反转
- 高潮机制
- 结局
- 标题

目标是：

```text
当前市场需求
+
观众情绪缺口
+
目标国家现实
+
原创人物
+
原创困境
+
原创爽感执行
=
新故事
```

# 四、模式路由

## 模式一：市场研究

只输出最新市场证据、头部题材、上升方向、饱和方向、情绪需求和机会空白。

## 模式二：高爽创意池

```text
实时市场研究
→ 5–10 个原创创意
→ 爽感引擎检查
→ 连载能力检查
→ 评分
→ 推荐前三
```

## 模式三：故事开发

输出人物关系、爽感承诺、爽点债务、连载发动机、完整故事线、全集结构表。

## 模式四：完整剧本

继续写到用户要求的每一集完整正文。

## 模式五：诊断与重写

```text
根问题
→ 爽感是否拖欠
→ 连载发动机
→ 人物主动性
→ 结构
→ 分集
→ 场景
→ 对白
→ 本地化
→ 连续性
→ 重写
```

## 模式六：小说或素材短剧化

读取：

`references/adaptation.md`

禁止逐章直接切成逐集。

`references/market-research.md`

# 七、创意评分

创意至少包含：

```yaml
创意:
  中文暂定名:
  类型:
  目标受众:
  一句话故事:
  主角:
  核心关系:
  外部目标:
  核心冲突:
  核心秘密:
  核心爽感承诺:
  观众最想看到什么被夺回来:
  第一次小爽:
  第一阶段大兑现:
  连载发动机:
  市场依据:
  本地化优势:
  原创差异:
```

默认评分：

```text
当前市场适配          15
开场吸引力            15
爽感强度与兑现速度    20
主角主动性            10
关系张力              10
连载能力              10
反转与揭秘空间        10
本地化可信度           5
原创差异化             5
-------------------------
总分                 100
```

高分不是“最像榜一”，而是当前需求强、爽感清楚、主角主动、执行方式新。

# 八、本地化

读取：

`references/localization.md`

禁止“中国故事换外国名字”。

必须检查当地：家庭、婚恋、职业、公司、阶层、医疗、教育、警务、法律、住房、货币和社交行为。

爽感保留心理机制，不照搬中国爽文表皮。

例如保留“权力翻转”，但在不同国家可以通过合同权利、董事会、继承、职业资格、法律程序、社区声誉等方式完成。

---

# 九、故事与人物

读取：

`references/story-development.md`

正式写正文前锁定：

```text
故事前提
主题问题
核心戏剧问题
主角外在目标
主角内在需求
核心关系
主要对抗力量
失败代价
完整故事线
最终结局
```

核心因果：

```text
因为 → 所以 → 但是 → 因此
```

拒绝“然后 → 然后 → 然后”。

---

# 十、爽感引擎必须单独过关

读取：

`references/satisfaction-engine.md`

进入全集结构前必须建立：

```yaml
爽感设计:
  核心爽感承诺:
  主角最初被夺走什么:
  主角最终要夺回什么:
  主要爽感类型:
  次级爽感类型:
  主角必须亲自完成的关键兑现:
  第一次小爽:
  第一次中爽:
  第一阶段大兑现:
  中段最大兑现:
  终极兑现:
```

同时维护爽点债务账本。

原则：

> 伤在哪里，爽尽量还在哪里。

不能不断建立痛点却不偿还。

---

# 十一、连载发动机与人物冲突

读取：

`references/series-engine-character.md`

进入全集结构前完成：

- 三集测试
- 闭合短剧失压测试
- 人物关系网
- 主角压力阶梯
- 对手策略升级
- 信息不对称设计

特别检查：

```text
如果现在把误会说开，故事是不是立刻结束？
如果秘密现在揭开，后面还有没有真实冲突？
第2、3、4集是否来自第1集的后果？
对手是否会根据主角行动换招？
```

发动机弱时先修发动机，不靠新增随机反派拖集数。

---

# 十二、全剧结构

结构方法可以使用三幕、四幕、五幕、十五节拍、英雄旅程、七点或自定义阶段，但不能为了模板增加无因果事件。

爽剧优先设计：

```text
全剧升级阶梯
+
阶段爽点大兑现
+
每集微型推进 / 获得 / 兑现
```

全剧规划必须先于逐集正文：

```text
完整故事
→ 全集结构表
→ 爽点债务与大兑现位置
→ 关键揭秘、伏笔、回收
→ 第1集正文
→ 更新状态
→ 第2集正文
→ ……
```

禁止一句创意直接自由生成几十集正文。

---

# 十三、逐集写作

默认一次正式写一集，整季大纲可以一次规划。

每集先建立：

```yaml
单集:
  集数:
  开场钩子:
  主角本集目标:
  主要压力:
  主角主动动作:
  对手反制:
  有效推进:
  新增关键信息:
  小兑现或阶段兑现:
  新增爽点债务:
  偿还爽点债务:
  关系变化:
  状态变化:
  结尾悬念:
  下一集必须承接:
```

如果：

```text
有效推进 = 无
小兑现或阶段兑现 = 无
状态变化 = 无
```

三项同时成立，本集默认判为无效拖集，必须重写。

# 十五、完整剧本写作

读取：

`references/screenplay-writing.md`

规则：

- 只写可见、可听、可演内容
- 默认全中文
- 场景晚进早出
- 每场有目标、阻力、策略、变化
- 对白是一种行动
- 解释尽量变成冲突筹码
- 主要人物必须有不同说话方式
- 主角不能长期依靠别人代打
- 不混入分镜、摄影和生成模型指令

---

# 十六、场景与对白诊断

读取：

`references/dialogue-scene-diagnostics.md`

先判断问题在对白还是场景结构。

重点检查：

- 同一种策略是否重复
- 解说对白是否过多
- 是否复述双方都知道的信息
- 是否过度解释心理
- 双人对话是否缺第三压力点
- 场景是否进得太早、退得太晚
- 爽点是否只靠口头羞辱和口头反击

# 二十一、最终完成标准

完整剧本必须满足：

```text
□ 目标国家明确
□ 市场驱动项目使用本次实时资料
□ 故事原创，不是热门作品换皮
□ 核心爽感承诺清晰
□ 前几集主角已经开始行动，不是一直挨打
□ 没有连续两集只有受压却无有效获得
□ 重要痛点都有对应爽点债务
□ 长期债务存在中间兑现
□ 主角核心胜利主要由自己完成
□ 对手会学习、反制和升级
□ 同一种爽法没有机械重复
□ 每集至少在推进、获得、兑现中有一项明显成立
□ 每集都产生状态变化
□ 大爽点都有前置因果，不是天降
□ 爽点之后有余震
□ 误会不是靠“不说一句话”硬拖
□ 尾钩来自后果，不是强行切断
□ 连载发动机能够持续产生新冲突
□ 人物知识、关系、时间、物品保持连续
□ 本地化符合目标国家现实
□ 默认向用户交付中文完整剧本
□ 没有混入分镜和视频生成内容
```

最终判断：

```text
爽剧不是“让主角受苦越久，最后越爽”。

而是：
期待建立得快，
主角行动得快，
小回报来得勤，
大回报来得准，
对手升级得狠，
故事始终向前。
```
