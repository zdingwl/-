# 海外短剧完整剧本技能 2.4

## 一、核心定位

本技能不是单一“爽剧 Skill”，而是一套可根据项目类型切换叙事模式的海外短剧完整编剧系统。

完整流程：

```text
确认目标国家
→ 本次实时市场研究（市场驱动项目）
→ 确定创作模式
→ 市场机会与原创创意池
→ 目标国家本地化
→ 故事前提 / 主题 / 核心戏剧问题
→ 人物 / 关系 / 对抗力量
→ 类型专项发动机
→ 连载故事发动机
→ 全剧宏观结构
→ 全集结构表
→ 伏笔 / 揭秘 / 回收规划
→ 单集剧情卡
→ 场景任务卡
→ 逐集完整剧本
→ 项目状态 / 故事设定总表 / 集间交接状态
→ 场景与对白诊断
→ 结构 / 人物 / 连续性 / 本地化 / 原创性修订
→ 最终中文完整剧本
```

当用户要求“完整剧本”时，最终必须写到：

```text
场次
+
动作
+
人物行为
+
完整对白
+
每集结尾
```

不能只交创意、梗概或分集简介。

# 二、最高优先级硬规则

## 1. 目标国家必须先确认

创建海外项目之前必须知道：

```yaml
目标国家:
```

如果用户未提供国家，先问：

> 这部短剧主要面向哪个国家或地区？

禁止默认美国，禁止把“海外、欧美、英文市场”自动等同美国。

多国项目记录主目标国家和次要市场；主目标国家控制市场研究、本地化和社会现实。

---

## 2. 最新市场必须本次实时检索

只要任务涉及：

```text
最新
当前
近期
热门
爆款
榜单
排名
趋势
增长
下载
收入
市场份额
现在流行什么
根据国外市场创作
```

必须在本次任务中进行外部实时检索。

模型训练知识、历史记忆只能用于：

- 编剧理论
- 通用概念
- 明确标注为历史背景的资料

禁止用于证明当前排名、当前热门题材、当前平台热度、当前受众偏好、当前下载收入或当前爆款。

没有实时证据时必须明确说明：

> 当前无法验证最新数据。

市场驱动项目读取：

`references/market-research.md`

---

## 3. 所有给用户看的内容默认只用中文

默认：

```yaml
剧本输出语言: 简体中文
对白输出语言: 简体中文
```

包括市场分析、创意、人物、分集、场景、动作、对白、审稿和终稿。

海外本地化指故事逻辑符合目标国家，不等于必须输出外语。

只有用户明确要求英文版、外语版或中外文对照时，才生成外语。

---

## 4. 学习市场，不复制作品

允许学习：

- 题材
- 情绪承诺
- 人物原型
- 关系模式
- 冲突机制
- 钩子类型
- 连载发动机
- 节奏规律

禁止复制：

- 人物姓名
- 独特人物组合
- 标志性场景
- 台词
- 独特道具
- 完整剧情节点顺序
- 特有反转
- 高潮机制
- 结局
- 标题

# 三、创作模式必须先路由

读取：

`references/creative-modes.md`

支持模式：

- 高爽商业
- 情感关系
- 悬疑 / 谜团
- 爱情 / 浪漫
- 喜剧
- 黑暗 / 惊悚
- 慢燃 / 文艺 / 人物驱动
- 混合类型

如果用户明确指定类型，尊重用户选择。

如果用户未指定，但要求“根据最新市场做项目”，先完成实时市场研究，再根据证据推荐合适的模式。

项目记录：

```yaml
创作模式:
  主模式:
  次模式:
  节奏速度:
  主要观众回报:
  允许延迟的内容:
  必须快速兑现的内容:
```

总原则：

> 慢可以，但不能拖；快可以，但不能空。

任何模式都不允许靠人物降智、无限误会、随机巧合或无后果事件强行续集。

# 四、专项模块按模式加载

## 高爽商业模式

当用户明确要爽剧、爽文改编、复仇、逆袭、身份翻转、高频回报时，读取：

`references/satisfaction-engine.md`

重点维护：

- 爽感承诺
- 爽点债务
- 主角主动性
- 兑现速度
- 爽法重复检查
- 阶段大兑现
- 终极兑现

注意：这些规则不是所有短剧的通用硬规则。

---

## 非爽剧模式

不强制使用“每集都要小爽、连续两集必须获得”等爽剧规则。

但仍必须有有效变化，例如：

```text
关系变化
认知变化
风险变化
目标变化
信息变化
人物选择变化
价值判断变化
```

悬疑可以延迟答案，但不能延迟推进。

情感可以慢热，但关系不能长期静止。

文艺可以少事件，但人物认知和关系位置必须变化。

喜剧可以松弛，但笑点必须来自人物与处境，并推动人物或剧情。

# 八、市场研究

读取：

`references/market-research.md`

必须：

1. 记录检索日期
2. 优先官方或第一方当前数据
3. 多平台取样
4. 区分持续热门、上升、饱和、下滑
5. 短剧与网文可以互相作为趋势信号，但不能混成同一榜单
6. 提取题材、人物、关系、情绪回报、钩子、连载机制
7. 不把单个平台前十当整个国家市场
8. 用户可见总结统一中文

# 九、创意评分按模式调整

通用评分框架：

```text
当前市场适配          15
开场吸引力            15
核心观众回报          15
人物主动性            10
关系 / 冲突张力       10
连载能力              15
反转 / 发展空间       10
本地化可信度           5
原创差异化             5
-------------------------
总分                 100
```

根据模式调整“核心观众回报”的判断：

- 爽剧看兑现与掌控感
- 情感剧看关系与情绪回报
- 悬疑看问题链与揭秘满足
- 爱情看吸引、阻碍、选择与关系推进
- 喜剧看人物处境与升级
- 惊悚看风险与生存压力
- 慢燃看人物变化与情绪余韵

高分不是“最像榜一”，而是当前需求强、类型承诺清楚、人物有行动、执行方式新。

# 十、本地化

读取：

`references/localization.md`

禁止：中国故事只换外国名字。

必须检查目标国家的家庭、婚恋、职业、公司、阶层、医疗、教育、警务、法律、住房、货币和社交行为。

类型机制可以跨文化保留，但具体实现必须本地化。

例如“权力翻转”可以保留，但不必照搬某个国家特有的下跪、认亲或董事长救场桥段。

---

# 十一、故事与人物

读取：

`references/story-development.md`

正式写正文前锁定：

```text
故事前提
主题问题
核心戏剧问题
主角外在目标
主角内在需求
核心关系
主要对抗力量
失败代价
完整故事线
最终结局
```

核心因果：

```text
因为 → 所以 → 但是 → 因此
```

避免：

```text
然后 → 然后 → 然后
```

---

# 十二、连载发动机与人物冲突

读取：

`references/series-engine-character.md`

进入全集结构前完成：

- 三集测试或对应长度压力测试
- 人物关系网
- 主角压力阶梯
- 对手策略升级
- 信息不对称设计

特别检查：

```text
如果一个误会现在说开，故事是不是马上结束？
如果一个秘密现在揭开，后面还有没有真实冲突？
第2、3、4集是否来自前集选择的后果？
对手是否会根据主角行动调整策略？
```

发动机弱时先修发动机，不靠随机新增反派和误会拖集数。

---

# 十三、全剧结构

结构方法可以使用三幕、四幕、五幕、十五节拍、英雄旅程、七点结构或自定义阶段，但不能为了模板增加无因果事件。

不同模式允许不同节奏。

统一要求：

```text
完整故事
→ 全集结构表
→ 关键转折 / 伏笔 / 揭秘 / 回收
→ 第1集正文
→ 更新状态
→ 第2集正文
→ ……
```

禁止一句创意直接自由生成几十集正文。

---

# 十四、逐集写作

默认一次正式写一集，整季大纲可以一次规划。

每集先建立：

```yaml
单集:
  集数:
  开场状态:
  开场钩子:
  本集职责:
  主角本集目标:
  主要压力:
  主角主动动作:
  对手反制:
  有效推进:
  新增关键信息:
  核心情绪或类型回报:
  关系变化:
  状态变化:
  结尾悬念:
  下一集必须承接:
```

高爽模式额外记录爽点债务与兑现。

悬疑模式额外记录线索、假设、误导和观众知识状态。

情感 / 爱情模式额外记录关系位置与未说出口的诉求。

# 十五、场景设计

正式写每场前明确：

```yaml
场景:
  编号:
  地点:
  时间:
  出场人物:
  戏剧问题:
  人物目标:
  阻碍:
  当前策略:
  对方反制:
  新信息:
  转折:
  场景前状态:
  场景后状态:
  结果:
```

没有变化的场景优先删除、合并或重写。

变化不一定是“胜负”，也可以是关系、认知、风险或价值判断的变化。

# 十六、完整剧本写作

读取：

`references/screenplay-writing.md`

核心规则：

- 只写可见、可听、可演的内容
- 默认全中文
- 场景尽量晚进早出
- 每场有目标、阻力、策略和变化
- 对白是一种行动
- 解说尽量变成冲突中的筹码
- 主要人物有不同说话方式
- 情绪尽量通过动作、选择、停顿、物件和关系表现
- 不混入分镜、摄影和生成模型指令

---

# 十七、场景与对白诊断

读取：

`references/dialogue-scene-diagnostics.md`

先判断问题是对白，还是场景本身没有目标、阻碍、代价和转折。

重点检查：

- 连续节拍是否一直使用同一种策略
- 解释型对白是否能变成筹码
- 人物是否复述双方都知道的信息
- 台词是否过度解释心理
- 双人对话是否缺少第三压力点
- 场景地点是否影响冲突
- 场景是否进得太早、退得太晚

---

# 十八、连续性与状态

```yaml
连续性:

  情绪状态:
  关系状态:
  伤势:
  持有物:

  各人物已知信息:
  各人物未知信息:
  各人物错误认知:
```

状态区分：已锁定、暂定、候选、已否决。

每集结束立即更新。

# 十九、小说与素材短剧化

读取：

`references/adaptation.md`

```text
找核心冲突
→ 找核心观众承诺
→ 找主角主动性

```

# 二十二、最终完成标准

任何完整剧本都必须满足：

```text
□ 目标国家明确
□ 市场驱动项目使用本次实时资料
□ 创作模式明确，不发生无意识类型漂移
□ 故事原创，不是热门作品换皮
□ 类型承诺持续兑现
□ 人物行为符合目标、知识和压力
□ 主角的选择持续制造后果
□ 对手或阻碍力量会根据主角行动变化
□ 连载发动机能够持续产生新冲突
□ 每集承担明确职责
□ 每场有戏剧功能与状态变化
□ 对白有行动、潜台词和人物差异
□ 信息、关系、风险或目标持续推进
□ 没有靠人物降智、无限误会和随机巧合拖集
□ 人物知识、关系、时间、物品保持连续
□ 本地化符合目标国家现实
□ 默认向用户交付中文完整剧本
□ 用户未明确要求外语时不主动附外语
```

模式专项附加标准：

- 高爽：检查爽点债务、兑现速度、主角主动性和爽法重复
- 悬疑：检查线索公平、知识状态、误导合理性和揭秘链
- 情感 / 爱情：检查关系变化、选择代价和情绪积累
- 喜剧：检查笑点是否来自人物与处境并推动剧情
- 惊悚：检查威胁逻辑、风险升级和角色应对
- 慢燃 / 文艺：检查人物认知和关系是否真正变化

最终原则：

```text
不是所有短剧都要“爽得快”，
但所有短剧都必须“变化得真”。

慢可以，但不能拖；
快可以，但不能空。
```
