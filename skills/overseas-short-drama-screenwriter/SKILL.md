# 海外短剧完整剧本技能 2.7

## 一、核心定位

本技能是一套可按项目类型切换叙事模式的海外短剧完整编剧系统。

它不是单一爽剧模板，也不是电影剧本压缩版，更不是传统电视剧拆碎版。

完整流程：

```text
确认目标国家
→ 本次实时市场研究（市场驱动项目）
→ 确定创作模式
→ 市场机会与原创创意池
→ 目标国家本地化
→ 故事前提 / 主题 / 核心戏剧问题
→ 人物 / 关系 / 人物弧光
→ 连载故事发动机
→ 全剧宏观结构
→ 短剧媒介转换
→ 全集结构表
→ 伏笔 / 揭秘 / 回收规划
→ 单集剧情卡
→ 场景任务卡 / 权力变化
→ 逐集完整中文短剧剧本
→ 项目状态 / 故事设定总表 / 连续性更新
→ 场景与对白诊断
→ 长篇一致性扫描
→ 剧本医生整剧诊断
→ 独立冷读质检
→ 修订
→ 最终中文完整剧本
```

用户要求“完整剧本”时，最终必须写到：

```text
集数
+
场次
+
动作
+
人物行为
+
完整对白
+
每集结尾
```

不能只交创意、梗概或分集简介。

# 二、四条最高优先级硬规则

## 1. 目标国家必须先确认

创建海外项目之前必须知道主目标国家。

如果用户只说“海外、欧美、英文市场、欧洲、拉美”等，而任务需要本地化，先确认主目标国家。

禁止默认美国。

主目标国家控制：

- 当前市场研究
- 社会制度
- 职业与公司逻辑
- 家庭与婚恋
- 阶层符号
- 货币
- 法律、医疗、学校、警务
- 人物行为与表达逻辑

---

## 2. 最新市场必须本次实时检索

只要任务涉及：

```text
最新 / 当前 / 近期 / 热门 / 爆款
榜单 / 排名 / 趋势 / 增长
下载 / 收入 / 市场份额
现在流行什么 / 根据国外市场创作
```

必须在本次任务中实际进行外部实时检索。

模型训练知识和历史记忆只能用于编剧理论、通用概念和明确标注的历史背景。

禁止用于证明当前榜单、当前爆款、当前平台热度和当前受众偏好。

市场驱动项目读取：

`references/market-research.md`

---

## 3. 所有给用户看的内容默认只用中文

默认：

```yaml
剧本输出语言: 简体中文
对白输出语言: 简体中文
```

包括市场分析、创意、人物、分集、场景、动作、对白、诊断和终稿。

海外本地化是“故事逻辑符合目标国家”，不等于必须输出外语。

只有用户明确要求英文版、其他外语版或中外文对照时，才生成外语。

---

## 4. 学习市场，不复制作品

允许学习：

- 题材
- 情绪承诺
- 人物原型
- 关系模式
- 冲突机制
- 钩子类型
- 连载发动机
- 节奏规律

禁止复制：

- 人物姓名
- 独特人物组合
- 标志性场景
- 台词
- 独特道具
- 完整剧情节点顺序
- 特有反转
- 高潮机制
- 结局
- 标题

市场研究的目标是发现需求和结构规律，再创作新的故事。

# 三、先选择创作模式

读取：

`references/creative-modes.md`

支持：

- 高爽商业
- 情感关系
- 悬疑 / 谜团
- 爱情 / 浪漫
- 喜剧
- 高压 / 惊悚
- 慢燃 / 文艺 / 人物驱动
- 混合类型

用户明确指定类型时，尊重用户选择。

用户未指定、但要求“根据最新市场做项目”时，先做实时市场研究，再根据证据推荐创作模式。

项目记录：

```yaml
创作模式:
  主模式:
  次模式:
  节奏速度:
  主要观众回报:
  允许延迟的内容:
  必须快速兑现的内容:
```

总原则：

> 慢可以，但不能拖；快可以，但不能空。

任何模式都不允许靠人物降智、无限误会、随机巧合或无后果事件强行续集。

# 四、专项模块按需加载

## 高爽商业

用户明确要爽剧、爽文改编、复仇、逆袭、身份翻转或高频回报时读取：

`references/satisfaction-engine.md`

重点维护：

- 爽感承诺
- 爽点债务
- 主角主动性
- 兑现速度
- 爽法重复
- 阶段大兑现
- 终极兑现

这些规则不是所有短剧的通用硬规则。

## 非爽剧模式

不强制“每集都要小爽”。

但必须持续发生至少一种有效变化：

```text
关系
认知
风险
目标
信息
人物选择
价值判断
```

悬疑可以延迟答案，但不能延迟推进。

情感可以慢热，但关系不能长期静止。

慢燃可以少事件，但人物认知与关系位置不能长期静止。

喜剧可以松弛，但笑点必须来自人物和处境，并推动人物或剧情。

# 六、市场研究

读取：

`references/market-research.md`

必须：

1. 记录检索日期
2. 优先官方或第一方当前数据
3. 多平台取样
4. 区分持续热门、上升、饱和和下滑
5. 短剧与网文可以互相作为趋势信号，但不能混成同一榜单
6. 提取题材、人物、关系、情绪回报、钩子和连载机制
7. 不把单个平台前十当整个国家市场
8. 报告区分“已验证当前事实”和“基于当前数据的创作判断”
9. 用户可见总结统一中文

# 七、原创创意池

市场驱动项目生成 5–10 个原创创意。

通用评分：

```text
当前市场适配          15
开场吸引力            15
核心观众回报          15
人物主动性            10
关系 / 冲突张力       10
连载能力              15
反转 / 发展空间       10
本地化可信度           5
原创差异化             5
-------------------------
总分                 100
```

“核心观众回报”按当前创作模式判断，不能拿爽剧标准去评分所有类型。

读取：

`references/localization.md`

禁止“中国故事只换外国名字”。

必须检查目标国家的：家庭、婚恋、职业、公司、阶层、医疗、教育、警务、法律、住房、货币和社交行为。

影响剧情因果的现实事实必须查证。

# 九、故事前提与人物

读取：

`references/story-development.md`

和：

`references/character-visual-dramaturgy.md`

正式写正文前锁定：

```text
故事前提
主题问题
核心戏剧问题
主角外在目标
主角内在需求
主角错误信念
核心关系
主要对抗力量
失败代价
人物弧证明方式
完整故事线
最终结局
```

核心因果：

```text
因为 → 所以 → 但是 → 因此
```

人物弧必须通过高代价选择证明，不用台词宣布“我成长了”。

重要心理变化优先转成动作、选择、停顿、物件处理和关系行为。

# 十、连载发动机与人物冲突

读取：

`references/series-engine-character.md`

进入全集结构前完成：

- 三集测试或对应长度压力测试
- 人物关系网
- 主角压力阶梯
- 对手策略升级
- 信息不对称设计
- 故事自然失压点判断

特别检查：

```text
如果一个误会现在说开，故事是不是马上结束？
如果一个秘密现在揭开，后面还有没有真实冲突？
后续集是否来自前集选择的后果？
对手是否会根据主角行动调整策略？
```

发动机弱时先修发动机，不靠随机新增反派和误会拖集数。

---

# 十一、全剧规划先于逐集正文

可以采用三幕、四幕、五幕、十五节拍、英雄旅程、七点结构或自定义阶段，但不能为了模板增加无因果事件。

统一顺序：

```text
完整故事
→ 全剧阶段结构
→ 短剧媒介转换
→ 全集结构表
→ 关键转折 / 伏笔 / 揭秘 / 回收
→ 第1集正文
→ 更新正式状态
→ 第2集正文
→ ……
```

禁止一句创意直接自由生成几十集完整正文。

完整正文默认按顺序逐集写；整季大纲可以一次规划。

---

# 十二、短剧媒介转换【所有类型必读】

正式进入全集结构和逐集正文之前，必须读取：

`references/short-drama-medium.md`

本层专门负责把通用电影、电视剧、小说编剧方法转换成短剧语言。

核心判断：

> 短剧不是更短的电影，也不是切碎的电视剧。

统一要求：

- 尽快建立当前问题
- 单集形成微型戏剧单元
- 单位时间保持较高有效变化密度
- 场景短而完整，不短而碎
- 信息进入冲突，不脱离剧情讲解
- 人物快速可识别，但仍有长期弧光
- 集尾来自本集后果，不靠机械切断
- 台词强调行动密度，不机械限制字数
- 慢燃允许低事件密度，但不允许零变化
- 不用固定秒数、固定反转次数替代戏剧判断

短剧专用的“有效变化”包括：

```text
目标变化
关系变化
权力变化
风险变化
信息变化
认知变化
人物选择变化
资源变化
秘密状态变化
观众预期变化
类型回报
```

如果一段戏只有说话速度快，却没有状态变化，仍然属于拖。

# 十三、单集剧情卡

每集先建立：

```yaml
单集:
  集数:
  开场状态:
  当前问题:
  开场钩子:
  本集职责:
  主角本集目标:
  主要压力:
  主角主动动作:
  对手反制:
  有效推进:
  新增关键信息:
  核心情绪或类型回报:
  关系 / 权力 / 风险 / 认知变化:
  结尾后果:
  结尾悬念:
  下一集必须承接:
```

单集最低逻辑：

```text
当前问题
→ 人物行动
→ 阻力 / 反制
→ 局面变化
→ 新后果或新问题
```

模式专项字段按需追加：

- 高爽：爽点债务、兑现
- 悬疑：线索、假设、误导、知识状态
- 爱情 / 情感：关系位置、未说出口的诉求
- 喜剧：错误策略、升级后果
- 高压 / 惊悚：风险和生存选择
- 慢燃：认知、关系距离、价值判断的微变化

# 十四、场景任务卡

正式写每场前读取：

`references/character-visual-dramaturgy.md`

和：

`references/short-drama-medium.md`

建立：

```yaml
场景:
  编号:
  地点:
  时间:
  出场人物:
  戏剧问题:
  人物目标:
  阻碍:
  当前策略:
  对方反制:
  新信息:
  转折:
  场景前状态:
  场景前优势方:
  优势来源:
  场景后状态:
  场景后优势方:
  不可逆后果:
  下一场为什么必须发生:
```

没有变化的场景优先删除、合并或重写。

变化不一定是胜负，也可以是关系、认知、风险、信息或价值判断。

短剧场景重点检查：

```text
谁在争取什么？
对方如何阻止？
策略有没有变化？
场景前后谁掌握更多信息或控制权？
发生了什么不可忽略的变化？
为什么下一场必须发生？
```

# 十五、完整剧本写作

读取：

`references/screenplay-writing.md`

核心规则：

- 只写可见、可听、可演的内容
- 默认全中文
- 场景尽量晚进早出
- 每场有目标、阻力、策略和变化
- 对白是一种行动
- 解说尽量变成冲突筹码
- 主要人物有不同说话方式
- 情绪尽量通过动作、选择、停顿、物件、距离和关系表现
- 心理变化如果重要，就让它改变人物下一步行为
- 短剧对白追求行动密度，不追求机械短句
- 不混入分镜、摄影和生成模型指令

---

# 十六、场景与对白诊断

读取：

`references/dialogue-scene-diagnostics.md`

和短剧媒介检查：

`references/short-drama-medium.md`

重点检查：

- 连续节拍是否一直使用同一种策略
- 解释型对白是否能变成筹码
- 人物是否复述双方都知道的信息
- 台词是否过度解释心理
- 双人对话是否缺少第三压力点
- 场景地点是否真正影响冲突
- 场景是否进得太早、退得太晚
- 场景前后权力、信息、关系或风险是否移动
- 是否出现“台词很多但剧情没动”的假快节奏
- 是否出现可整段删除却不影响剧情的空转段落
- 集尾是否来自本集后果，而不是机械切断

---

# 十七、长篇连续性必须持续维护

多集项目读取：

`references/story-continuity.md`

持续检查七类状态：

```text
人物事实
时间与空间
人物知识
关系状态
物件 / 资源 / 证据
世界与现实规则
因果 / 承诺 / 伏笔
```

每集结束立即更新正式集间状态。

长剧中段增加检查密度，重点防止：

- 人物知识漂移
- 关系无原因重置
- 重复冲突
- 资源状态混乱
- 伏笔遗忘
- 已解决问题被无原因重新使用

发现事实冲突时，不默认“最新写的就是真的”，优先遵守用户锁定事实和正式故事设定。

---

# 十八、小说与素材短剧化

读取：

`references/adaptation.md`

并强制经过：

`references/short-drama-medium.md`

正确顺序：

```text
找核心冲突
→ 找核心观众承诺
→ 找主角主动性
→ 提取关键因果链和可见行动
→ 压缩人物和支线
→ 重排信息与秘密
→ 找阶段状态变化
→ 重新设计单集问题与承接
→ 按创作模式重构节奏与回报
→ 再划分单集
```

禁止：

```text
小说第1章 = 短剧第1集
电影前3分钟 = 短剧第1集
电视剧一场戏 = 短剧一集
```

短剧集界应优先落在“局势发生变化”的地方，而不是机械字数或分钟边界。

---

# 十九、剧本医生终稿诊断

完整初稿或重要阶段稿完成后读取：

`references/script-doctor.md`

按层诊断：

```text
类型承诺
→ 故事前提
→ 主角主动性
→ 人物弧
→ 连载发动机
→ 全剧结构
→ 短剧媒介适配
→ 多线交织
→ 分集功能
→ 场景权力变化
→ 对白与潜台词
→ 视觉化
→ 连续性
→ 本地化
→ 原创性
```

必须先指出最大根问题，再给出修复方案。

不要拿对白润色掩盖结构问题。

短剧专项额外诊断：

```text
哪里进入问题太慢？
哪里信息很多但没有戏？
哪里一整集没有有效变化？
哪里集尾只是强行切断？
哪里把电影/电视剧的铺垫原样搬进短剧？
哪里为了“快”牺牲了因果或情绪？
```

# 二十、独立质检

重要阶段读取：

`references/independent-review.md`

区分：

```text
写作时自检
机械可验证检查
独立冷读
```

写作者自己的自检不能自动当作终稿放行。

理想的独立冷读应尽量使用与创作过程隔离的上下文，只读取正式剧本、必要设定和锁定规则，不读取作者的自我解释和先前结论。

如果当前环境不能真正隔离，必须明确标记为：

> 同上下文复检，仅供建议，不等同独立冷读。

独立质检必须引用具体剧情证据。

推荐在以下阶段进行：

- 创意和故事前提锁定前
- 全集结构表完成后
- 前 3–5 集样稿后
- 长剧中段
- 完整初稿后
- 最终交付前

# 二十一、修订顺序

默认按以下层级：

```text
第一轮：类型承诺与核心观众回报
第二轮：故事前提与连载发动机
第三轮：主角主动性、人物弧与关系
第四轮：全剧结构、多线交织与阶段转折
第五轮：短剧媒介适配与全集切分
第六轮：分集职责与有效变化密度
第七轮：场景权力、价值与策略变化
第八轮：对白、潜台词与人物声音
第九轮：视觉戏剧化
第十轮：目标国家本地化
第十一轮：长篇连续性、知识状态与伏笔回收
第十二轮：去人工智能腔与原创性
第十三轮：独立质检后的定向修复
```

高爽模式额外检查爽感引擎与爽点债务。

`references/quality-gates.md`

# 二十二、Skill 自身必须做回归测试

本规则用于维护 Skill 本身，不是每次写剧本都要向用户展示。

大版本升级时读取：

`evaluations/README.md`

`evaluations/rubric.md`

`evaluations/cases.md`

测试方法：

```text
固定同一输入
→ 旧版 Skill 生成
→ 新版 Skill 生成
→ 隐藏版本标签
→ 使用统一评分表盲评
→ 检查类型是否退化
→ 检查规则是否过拟合
→ 决定是否升级主版本
```

重点防止：

- 所有类型越来越像爽剧
- 所有故事越来越像同一结构
- 人物为了满足规则而机械行动
- 为了反转而反转
- 为了潜台词而不说人话
- 为了视觉化而堆无意义动作
- 为了短剧“快节奏”而牺牲人物、因果和情绪
- 把“高有效变化密度”错误理解成“每隔固定秒数必须反转”

至少保留部分隐藏测试案例，避免针对固定测试题优化过度。

# 二十四、完整剧本完成标准

任何完整短剧剧本都必须满足：

```text
□ 目标国家明确
□ 市场驱动项目使用本次实时资料
□ 创作模式明确，没有无意识类型漂移
□ 故事原创，不是热门作品换皮
□ 类型承诺持续兑现
□ 人物有外在目标、内在需求和可验证的人物弧
□ 人物行为符合目标、知识和压力
□ 主角的选择持续制造后果
□ 对手或阻碍力量会根据主角行动变化
□ 连载发动机能够持续产生新冲突
□ 已经过短剧媒介转换，而不是电影 / 电视剧直接压缩或切碎
□ 全剧阶段能够重新落到短剧单集结构
□ 每集承担明确职责
□ 每集至少存在一种有效状态变化
□ 开场能够尽快建立当前问题
□ 场景短而完整，不是没有因果的碎片
□ 信息进入冲突，不依赖长篇讲解
□ 关键场景存在权力、关系、信息或风险移动
□ 重要心理变化尽量通过行为和选择表现
□ 对白有行动、潜台词和人物差异
□ 不使用固定秒数、固定反转次数代替戏剧判断
□ 集尾主要来自本集行为后果，不依赖机械切黑
□ 没有靠人物降智、无限误会和随机巧合拖集
□ 长剧人物事实、时间、知识、关系、物件和规则保持连续
□ 长剧中段已进行加密连续性检查
□ 本地化符合目标国家现实
□ 默认向用户交付中文完整剧本
□ 用户未明确要求外语时不主动附外语
□ 已经过剧本医生整剧诊断
□ 重要项目完成独立质检或明确标记质检级别
□ 已经过结构、人物、短剧媒介、场景、对白和连续性修订
□ 没有混入下游分镜和视频生成内容
```

模式专项附加标准：

- 高爽：检查爽点债务、兑现速度、主角主动性和爽法重复
- 悬疑：检查线索公平、知识状态、误导合理性和揭秘链
- 情感 / 爱情：检查关系变化、选择代价和情绪积累
- 喜剧：检查笑点是否来自人物与处境并推动剧情
- 高压 / 惊悚：检查威胁逻辑、风险升级和角色应对
- 慢燃 / 文艺：检查人物认知和关系是否真正变化

最终原则：

```text
短剧不是更短的电影，
也不是切碎的电视剧。

不是所有短剧都要爽得快，
但所有短剧都必须变化得真。

短剧真正的快，
是单位时间里的有效变化更密，
而不是人物说得更快、吵得更多、反转得更机械。

人物不是被描述成什么样，
而是在有代价的选择里证明自己是什么样。

长剧不是靠记忆维持一致，
而是靠正式状态维持连续。

慢可以，但不能拖；
快可以，但不能空。
```
