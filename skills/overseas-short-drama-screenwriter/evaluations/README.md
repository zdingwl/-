# 技能回归测试

用于比较不同版本的编剧 Skill，避免“规则越来越多，但剧本反而越来越模板化”。

核心原则：

> Skill 升级必须经过同题盲测，而不是只看规则写得更长。

## 一、测试对象

每次大版本升级至少比较：

```text
旧版 Skill
VS
新版 Skill
```

使用完全相同的项目输入、目标国家、题材、集数和输出要求。

评审阶段不告诉评审哪个是新版，尽量避免版本偏见。

## 二、测试集结构

建议长期保留三类案例：

1. 固定基准案例：每个版本都重复测试，用于观察长期变化
2. 类型覆盖案例：爽剧、悬疑、爱情、情感、喜剧、惊悚、慢燃等
3. 隐藏案例：不参与日常调规则，只在大版本验收时使用，防止过拟合

## 三、测试流程

```text
冻结输入
→ 旧版生成
→ 新版生成
→ 隐藏版本标签
→ 按统一量表评分
→ 记录胜负原因
→ 检查是否出现规则过拟合
→ 决定是否升级主版本
```

不能因为新版某一项更强，就忽略其它维度明显退化。

## 四、重点观察的退化

- 所有故事越来越像同一个结构
- 每集都机械出现同一种钩子
- 每个角色都像在执行规则而不是生活
- 为了满足“反转”而硬造反转
- 为了满足“人物弧”而让人物突然变化
- 为了满足“潜台词”而故意不说人话
- 为了满足“视觉化”而堆无意义动作
- 为了满足“快节奏”而丢失因果和情绪
- 为了满足“爽点”而把所有类型都写成爽剧

## 五、通过标准

新版只有在以下条件基本成立时才进入主版本：

- 总分不低于旧版
- 关键类型没有明显退化
- 没有新增严重模板化问题
- 长篇连续性至少不差于旧版
- 类型模式没有被单一规则吞掉
- 中文可读性和人物自然度没有下降

评分细则见 `rubric.md`。

测试题见 `cases.md`。
