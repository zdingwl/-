# 连载发动机与人物冲突深度规则

用于：创意已经确认，但还没有进入完整分集正文之前。目标是证明这个故事不仅“开头好看”，而且能持续产生新的冲突、选择、关系变化和情绪回报。

---

# 1. 连载发动机不是题材标签

以下都不是发动机：

- 豪门
- 黑帮
- 狼人
- 复仇
- 隐藏身份
- 先婚后爱
- 重生

它们只是题材或设定。

真正的连载发动机回答：

```text
为什么第1集结束后还有第2集？
为什么一个秘密揭开后故事没有结束？
为什么男女主坦白后仍有新的问题？
为什么反派不会只用同一种方法阻止主角？
为什么观众能持续获得同类情绪，但每次又不重复？
```

---

# 2. 发动机四件套

每个系列项目至少明确：

```yaml
series_engine:
  concept_container:
  recurring_conflict:
  thematic_opposition:
  repeatable_story_pattern:
```

解释：

- **概念容器**：故事发生在什么世界或关系结构中。
- **持续冲突**：什么矛盾不会轻易一次解决。
- **主题对立**：两种价值不断通过人物选择发生碰撞。
- **可重复故事模式**：每集怎样产生“同类但不同”的故事。

---

# 3. 三集测试

完成核心创意后，不急着写几十集。

先快速回答：

```text
第2集自然会发生什么？
第3集自然会发生什么？
第4集自然会发生什么？
```

要求：

- 不能只是第1集同一冲突换地点
- 不能靠随机新人物硬制造麻烦
- 必须来自人物关系、外部目标、秘密、资源或对手策略

如果三集都很难自然产生，说明发动机可能不成立。

---

# 4. 闭合短剧用“失压测试”

海外竖屏短剧很多是闭合型，不需要证明能拍100集。

因此不要机械套长期电视剧标准。

改用：

```text
核心物质目标什么时候会自然结束？
核心秘密什么时候必须公开？
核心关系什么时候必须做最终选择？
反派的资源什么时候耗尽？
```

把这些汇合点作为“发动机失压点”。

合理集数应来自：

> 故事什么时候自然失去继续产生高质量冲突的能力。

而不是：

> 用户想要80集，所以硬拖到80集。

---

# 5. 四种发动机并行

强短剧通常不只靠一种发动机。

建议至少有两种以上：

```text
关系发动机
外部目标发动机
秘密 / 信息发动机
反派发动机
资源 / 身份发动机
```

例如：

```text
关系发动机：男女主互相吸引，但目标冲突
外部发动机：女主必须夺回公司控制权
秘密发动机：男主隐瞒自己参与过当年的并购
反派发动机：前未婚夫每次根据女主的新行动升级打击
```

这样即使一个误会解决，故事仍然成立。

---

# 6. 人物网必须自动制造冲突

不要只设计“主角 + 爱人 + 反派”。

建立：

```yaml
character_network:
  character:
    wants_from_protagonist:
    needs_from_protagonist:
    hides_from_protagonist:
    can_take_from_protagonist:
    can_give_protagonist:
    conflict_of_interest:
    loyalty_limit:
```

每个主要配角至少拥有自己的目标。

配角不是为了给主角递信息。

---

# 7. 人物真相由压力下的选择揭示

人物卡里写“善良、聪明、冷酷、独立”没有意义，除非剧情能验证。

为主要人物建立压力阶梯：

```yaml
pressure_ladder:
  normal_state_choice:
  mild_pressure_choice:
  social_loss_choice:
  financial_or_status_loss_choice:
  relationship_loss_choice:
  extreme_pressure_choice:
  line_they_claim_they_will_never_cross:
  condition_under_which_they_might_cross_it:
```

人物弧不是“性格标签变了”，而是：

> 在越来越高的代价下，人物做出了与开篇不同的选择。

---

# 8. 主角必须主动制造后果

每个阶段检查：

```text
主角做了什么选择？
这个选择造成了什么后果？
后果为什么迫使主角再次行动？
```

优先：

```text
人物选择
→ 世界反应
→ 结果比预期更复杂
→ 人物升级策略
```

禁止长期依赖：

```text
主角被欺负
→ 别人来救
→ 主角再次被欺负
```

---

# 9. 对手必须会学习

弱反派：

```text
每集重复威胁主角
```

强对手：

```text
观察主角行动
→ 判断主角弱点
→ 调整策略
→ 攻击新的层面
```

建立对手策略升级表：

```yaml
antagonist_strategy:
  current_goal:
  current_resource:
  first_method:
  protagonist_counter:
  adapted_method:
  escalation_cost:
  final_leverage:
```

冲突升级必须改变层级，例如：

```text
羞辱
→ 关系破坏
→ 资源封锁
→ 身份曝光
→ 法律 / 财务后果
→ 不可逆选择
```

不要求固定顺序，但不能一直重复同一种攻击。

---

# 10. 错误信念与真正需要

主要人物至少明确：

```yaml
inner_engine:
  conscious_desire:
  false_belief:
  why_the_belief_once_helped:
  what_now_makes_it_harmful:
  internal_need:
  proof_scene_at_end:
```

“错误信念”不能只是抽象缺点。

例如：

弱：
> 她不相信爱情。

更具体：
> 她相信只有保持经济和情感上的绝对独立，才不会再次被任何人控制。

这会直接影响她的选择。

---

# 11. 关系发动机

核心关系写清：

```yaml
relationship_engine:
  what_a_wants:
  what_b_wants:
  shared_need:
  incompatible_goal:
  attraction_or_dependency:
  hidden_information:
  power_source_a:
  power_source_b:
  breaking_point:
  what_must_change_for_them_to_end_together_or_apart:
```

关系推进必须来自事件，而不是作者宣布：

```text
他们越来越喜欢彼此。
```

应该有可见证据：

- 谁第一次冒险替谁承担代价
- 谁第一次说出不愿说的真话
- 谁第一次拒绝控制对方
- 谁第一次把关键资源交给对方
- 谁在利益冲突中做出关系选择

---

# 12. 信息不对称是短剧发动机

为关键秘密记录四类信息状态：

```text
作者知道
观众知道
人物A知道
人物B知道
```

可制造：

- 悬念：观众不知道，但知道有问题
- 惊讶：观众和人物同时发现
- 戏剧反讽：观众知道，人物不知道
- 误判：人物相信错误信息

不要所有秘密都靠“误会不说清”。

如果一个冲突只需要一句正常沟通就能解决，必须给出可信原因：

- 法律风险
- 关系成本
- 职业保密
- 自尊
- 真实证据不足
- 说出真相会伤害第三人
- 人物错误信念

---

# 13. 故事模式检查

每隔若干集，应当仍能回答：

```text
观众为什么还在看这部剧？
他们期待的核心情绪是什么？
本集如何兑现同一种情绪，但用新的事件？
```

例如：

```text
观众期待“被低估的人逐步夺回控制权”
```

每次兑现可以不同：

- 工作场合反击
- 家庭关系夺回发言权
- 法庭获得证据优势
- 爱情关系拒绝不平等条款

同一情绪，不同戏剧执行。

---

# 14. 发动机终审

进入完整分集前检查：

```text
□ 第2–4集能自然产生
□ 不是只有一个误会支撑全剧
□ 至少两种发动机并行
□ 主角会主动制造后果
□ 对手会根据主角行动换招
□ 核心关系存在真实利益冲突
□ 秘密能够分层揭露
□ 每次小胜都会产生新代价
□ 知道故事什么时候自然失压
□ 目标集数与失压点基本匹配
```

核心原则：

> 好的连载不是“不断增加新事件”，而是同一组人物与目标不断产生新的后果。
