# 剧本项目调度与状态管理

用于长篇、连续短剧、跨会话续写和多轮修改。目标不是增加新的编剧理论，而是保证已经确认的决策不会被后续写作重新发明。

---

# 1. 核心原则

长篇剧本最常见的问题不是不会写一句台词，而是：

- 上一次确认的设定被忘记
- 人物关系被重新定义
- 已经埋过的伏笔被再次埋一遍
- 已推翻方案重新混回正文
- 一次修改牵连前文，但没有记录
- 下一次会话从头讨论已经确定的问题

因此持续项目必须维护一份“项目状态表”。

---

# 2. 项目状态表

建议维护：

```yaml
project_state:
  project_name:
  target_country:
  current_stage:
  current_episode:
  current_draft:
  last_updated:

  locked_decisions:
  assumed_decisions:
  proposed_decisions:
  rejected_decisions:

  next_action:
```

状态含义：

```text
已锁定：用户已经确认，不得擅自修改
暂定：为了推进工作做出的合理假设，后续可以修正
候选：只是方案之一，不能自动写成正典
已否决：明确淘汰，后续不得重新混入
```

---

# 3. 决策日志

凡是改变重要设定，都记录：

```yaml
decision_log:
  - date:
    changed_item:
    old_value:
    new_value:
    reason:
    affected_episodes:
```

必须记录的变化包括：

- 主角身份
- 核心关系
- 反派身份或目标
- 世界规则
- 重要秘密
- 结局
- 集数
- 核心反转
- 时间线
- 重大人物生死
- 关键道具归属

如果只是改一句台词，不需要进入决策日志。

---

# 4. 每次继续写之前

只读取足够恢复项目的信息，不要把整个项目从头重新推演。

优先读取：

```text
1. 当前阶段
2. 已锁定决策
3. 最近决策日志
4. 上一集交接状态
5. 当前未解决问题
6. 当前伏笔与回收状态
```

然后用内部方式确认：

```text
现在是什么项目？
写到哪一集？
上一集结束时发生了什么？
本集必须承接什么？
哪些设定不能改？
```

除非用户主动要求重构，否则不要重新讨论已经锁定的内容。

---

# 5. 项目阶段

海外短剧项目推荐阶段：

```text
阶段0  目标国家与项目参数
阶段1  实时市场研究
阶段2  原创创意与选题确认
阶段3  故事前提、主题与核心冲突
阶段4  人物网、关系网、连载发动机
阶段5  全剧结构与结局
阶段6  全集结构表、伏笔和揭秘规划
阶段7  单集剧情卡
阶段8  逐集完整剧本
阶段9  连续性与结构修订
阶段10 终稿
```

已有材料时，从最早缺失阶段开始，不必强制从阶段0重做。

---

# 6. 阶段通过原则

通过标准用于发现问题，不用于机械阻断用户。

每阶段结束至少问：

```text
这个阶段最重要的决定是否已经明确？
后面是否会因为这里模糊而大量返工？
有没有把“候选方案”误当“已确认事实”？
```

如果用户要求跳过某阶段，可以继续，但要在项目状态中标记：

```text
该阶段未完全锁定
```

后续出现问题时优先回查该阶段。

---

# 7. 不要按阶段拆给完全独立的作者

故事前提、人物、结构和场景高度耦合。

禁止：

```text
一个模型只写人物
另一个模型只写结构
第三个模型完全不知道前两者为什么这么设计
```

可以并行的是“只读审稿”：

- 结构审稿
- 人物审稿
- 场景审稿
- 对白审稿
- 本地化审稿
- 连续性审稿

最后由主线统一决定是否修改。

---

# 8. 一次只正式写一集

可以一次规划整季，但正式正文按集串行：

```text
整季结构锁定
→ 第1集
→ 更新交接状态
→ 第2集
→ 更新交接状态
→ ……
```

下一集不得只依赖模糊记忆。

---

# 9. 集间交接状态

```yaml
handoff_state:
  episode:
  story_time:
  locations:
  character_locations:
  character_goals:
  emotional_states:
  relationship_states:
  injuries:
  possessions:
  money_and_resources:
  knowledge_by_character:
  secrets_revealed:
  lies_currently_believed:
  setups_planted:
  setups_paid:
  unresolved_questions:
  antagonist_next_move:
  next_episode_must_address:
```

特别注意：

**人物知道什么、人物不知道什么、人物误以为什么**，必须分开记录。

---

# 10. 修改时的回退机制

如果写到第20集发现问题，不要只改第20集句子。

先判断根问题属于哪一层：

```text
对白问题？
场景问题？
单集问题？
人物动机问题？
连载发动机问题？
全剧结构问题？
故事前提问题？
```

从最早出错的层级修复。

例如：

```text
对白写不动
↓
可能不是对白问题
↓
人物没有真正目标
↓
回人物层修改
```

---

# 11. 项目状态必须保持精简

项目状态表只保存结论，不保存长篇推导。

完整：

- 市场报告
- 故事大纲
- 分集大纲
- 正式剧本

应当作为独立文档。

项目状态只记录：

```text
文件是什么
当前版本
已经确认什么
下一步是什么
```

否则状态文件本身会膨胀到无法有效读取。

---

# 12. 会话结束检查

每轮工作结束前确认：

```text
□ 当前阶段已更新
□ 新确认的重要决策已记录
□ 被否决方案没有留在“候选”中
□ 当前集交接状态已更新
□ 未解决问题已记录
□ 下一步明确
```

核心目标：

> 下一次继续写时，不重新发明这部剧。
