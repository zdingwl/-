# 独立质检规则

本文件用于重要阶段稿、完整初稿和终稿前的独立复检。

核心原则：

> 写作者自己的自检，只能发现问题；真正的阶段放行，最好由与创作过程隔离的第二视角完成。

独立质检不是“换个语气再看一遍”，而是尽量减少前面创作意图对判断的污染。

---

# 一、三层检查

## 第一层：写作时自检

由当前写作流程完成。

检查：

- 当前集是否完成职责
- 人物是否符合状态
- 场景是否有变化
- 台词是否有行动
- 是否出现明显连续性问题

作用：快速发现局部问题。

不能因为自检通过，就自动认定整剧已经可以交付。

---

## 第二层：机械检查

只检查可以明确判断的项目，例如：

- 集数和场次编号是否缺失或重复
- 人名是否漂移
- 已死亡人物是否无解释重新出现
- 人物是否同一时间出现在明显冲突的地点
- 已丢失或损坏的物件是否无解释恢复
- 外语是否误混入默认中文稿
- 已登记伏笔是否长期没有状态
- 人物是否使用了自己尚未知道的信息

机械检查不能判断：

- 好不好看
- 感不感人
- 爽不爽
- 悬疑是否抓人
- 对白是否有生命感
- 人物是否真正立体

这些仍然必须由完整读稿判断。

---

## 第三层：独立冷读

正式重要阶段推荐进行。

理想状态：

- 使用与创作上下文隔离的新审稿上下文
- 只提供正式剧本、必要设定和本项目锁定规则
- 不提供“作者本来想表达什么”
- 不提前告诉审稿者“这里已经通过”
- 不提供前一次审稿的结论作为暗示

如果当前工具或运行环境无法实现真正隔离，必须明确标记为：

> 同上下文复检，仅供建议，不等同独立冷读。

禁止模型假装自己已经进入独立上下文。

---

# 二、独立质检必须回答的问题

无论什么类型，至少回答：

```text
这版最明显的根问题是什么？
哪里最容易让观众失去兴趣？
哪一段如果删除，整体几乎不受影响？
哪一个人物行为最不像他自己？
哪一个重要转折最缺因果？
哪一个场景主要靠解释而不是戏剧行动？
哪一条线最弱？
哪里存在设定、时间、知识或关系矛盾？
结尾是否真正回应了开篇承诺？
```

类型专项：

- 高爽：爽点是否拖欠、兑现是否精准、主角是否主动
- 悬疑：线索是否公平、答案是否可以由前文推理、误导是否作弊
- 爱情/情感：关系变化是否有事件依据、情绪爆发是否有积累
- 喜剧：笑点是否来自人物和处境、升级是否有效
- 惊悚：风险是否真实、角色是否靠降智制造危险
- 慢燃：事件可以少，但人物认知与关系是否持续变化

---

# 三、证据化审稿

独立质检不能只写：

> 节奏不错。
> 人物比较立体。
> 建议加强冲突。

必须引用具体证据：

```yaml
问题:
  位置:
  具体现象:
  为什么成立:
  对观众的影响:
  根因:
  修复方向:
  需要保护的已有优点:
```

优先指出 3–7 个最重要问题，不要为了显得认真列几十条琐碎意见。

---

# 四、独立质检的优先级

问题按以下顺序处理：

```text
硬事实 / 连续性错误
→ 类型承诺失败
→ 主角与核心人物问题
→ 连载发动机
→ 全剧结构
→ 分集功能
→ 场景功能
→ 对白与视觉表达
→ 文字润色
```

上游问题没修好时，不要靠下游润色掩盖。

---

# 五、阶段放行

推荐对以下节点做独立质检：

1. 创意和故事前提锁定前
2. 全集结构表完成后
3. 前 3–5 集样稿完成后
4. 中段完成后
5. 完整初稿完成后
6. 最终交付前

长剧中段必须单独审，因为大量一致性和重复问题容易在中段积累。

---

# 六、独立质检结论

只允许以下四类：

```text
通过
有条件通过
需要局部重写
需要结构级重写
```

结论必须附：

- 最大根问题
- 必改项
- 可选优化项
- 修复后需要重新检查的范围

核心原则：

> 审稿的目标不是证明写得不错，而是尽早找出会让整部剧失败的问题。
