# 故事连续性

用于维护多集项目中的人物、时间、关系、信息、物件、资源和世界规则状态。

核心原则：长项目不能依赖模糊记忆，必须维护可核对的正式状态。

## 一、连续性七类检查

### 1. 人物事实
检查姓名、年龄、身份、职业、家庭关系、婚姻状态、重要前史、能力边界、身体状态和长期习惯。

### 2. 时间与空间
检查日期、昼夜、事件先后、旅行时间、恢复周期、人物位置和场景之间是否存在不可能的移动。

### 3. 人物知识状态
每个重要秘密至少区分：作者知道、观众知道、人物分别知道什么，以及人物当前有哪些错误判断。

重点检查：
- 不该知道的人是否提前知道
- 已经知道的人是否重复“第一次发现”
- 人物是否使用从未获得的信息做决定
- 已经解除的问题是否被无原因重置

### 4. 关系状态
记录信任、敌意、依赖、爱情、联盟、背叛和权力关系。关系变化必须有事件依据。

### 5. 物件、资源与证据
检查关键物件的当前持有人、当前状态、是否转移、是否公开、是否已经消耗；钱、股份、账户、证件、手机、录音、合同等资源也必须前后一致。

### 6. 世界规则与现实规则
检查法律、医疗、学校、公司治理、财务、警务，以及超自然、科幻或特殊世界规则。一旦锁定，后续不能为了方便剧情随意改变。

### 7. 因果与承诺
检查重大事件是否留下后果，人物承诺是否被遗忘，伏笔是否处理，重大资源变化是否改变后续策略，重要秘密公开后世界是否真的发生变化。

## 二、中段加密检查

长剧中段最容易出现重复冲突、知识漂移、关系重置、能力漂移、伏笔遗忘和资源状态混乱。

推荐：

```text
前段：常规检查
中段：加密检查
后段：回收检查
```

例如 60 集项目可以参考：
- 1–15 集：每 5 集一次阶段检查
- 16–45 集：每 3–5 集一次检查
- 46–60 集：重点检查伏笔、信息和结局回收

这只是参考，不是固定规则；项目越复杂，检查越密。

## 三、正式事实表

```yaml
事实:
  内容:
  状态: 已锁定 / 暂定 / 候选 / 已否决
  来源类型: 用户明确提供 / 实时资料 / 已写剧本 / 模型创作提案
  首次出现:
  最近确认:
  影响人物:
  影响后续:
```

候选设定不能因为在讨论中出现过，就自动变成正式事实。

## 四、每集结束后的最小更新

```yaml
集间状态:
  集数:
  剧中时间:
  人物位置:
  当前目标:
  关系变化:
  新增已知信息:
  新增误解:
  新增或失去资源:
  关键物件状态:
  身体状态:
  已公开秘密:
  新增伏笔:
  已回收伏笔:
  仍未解决的问题:
```

下一集必须先读取上一份正式状态。

## 五、错误等级

### 一级：硬冲突
如同一时间出现在两个地方、人物使用自己尚未知道的信息、关键物件状态前后互斥、时间线无法成立。必须优先修复。

### 二级：逻辑漂移
如人物态度变化缺过渡、能力水平漂移、关系突然重置、已经解决的问题无新原因再次出现。通常需要局部或结构性修复。

### 三级：弱连续性
如小道具状态不明、称呼偶尔不一致、次要日期模糊。终稿前清理。

## 六、事实冲突时的优先级

```text
用户明确锁定
→ 已公开并反复成立的重要剧情事实
→ 故事设定总表中的锁定事实
→ 较早正式剧本事实
→ 暂定设定
→ 模型临时提案
```

如果必须修改已锁定事实，先分析会影响哪些集、人物动机、伏笔、对白和结局。

## 七、终稿检查

至少确认：

```text
人物事实有没有互相矛盾？
时间线能不能成立？
人物知道什么是否一致？
关系变化有没有事件依据？
关键物件和证据去了哪里？
世界规则有没有被剧情偷偷改写？
重大事件有没有真正留下后果？
所有重要伏笔是否已经处理？
```

核心原则：长剧的一致性来自可核对的正式状态，而不是依赖记忆。
