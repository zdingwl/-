# Level 2 — 改编、修订、连续性与格式（111–120）

## 111. Adaptation Function

**定义**：改编优先保留源元素承担的功能，而不是逐句逐场保留形式。

**机制**：不同媒介擅长不同表达，功能忠实才能兼顾识别度与可看性。

**诊断**：某源元素真正提供的是因果、情绪、关系、主题还是世界信息？

**常见失败**：只问‘删不删’，不问‘它为什么存在’。

**修复**：为每个关键元素写 original_function 和 new_screen_function，再决定 KEEP/TRANSFORM/MERGE/MOVE/CUT/INVENT。

## 112. Adaptation Decision Matrix

**定义**：用统一决策语言记录改编取舍及影响。

**机制**：显式记录可以防止压缩后动机断裂，也让后续重写可追溯。

**诊断**：每个重大删除/合并是否知道会影响哪些角色、伏笔和后续事件？

**常见失败**：凭感觉删支线；后面发现 Setup 消失。

**修复**：维护 affected_elements 和 risk，任何高风险 CUT/MERGE 都做依赖检查。

## 113. Interior Externalization

**定义**：把小说内部意识转化为可见行为、选择、关系与后果。

**机制**：屏幕主要依靠视听信息；真正外化后，观众不需要旁白也能理解变化。

**诊断**：关掉旁白，人物的核心心理转折是否仍成立？

**常见失败**：把内心独白直接分配给对白；用配角替主角解释。

**修复**：优先选择、动作、策略、道具、空间和信息控制；旁白只作为明确形式策略。

## 114. Chapter-to-Screen Mapping

**定义**：章节是阅读组织单位，不等于场景、Sequence 或 Episode。

**机制**：影视单元应按目标、转折与状态变化划分。

**诊断**：章节边界是否恰好对应戏剧变化，还是只是作者换 POV/时间？

**常见失败**：机械一章一集；集数随章节长度波动。

**修复**：先抽取全书因果和不可逆节点，再重组 Sequence/Episode，最后切 Scene。

## 115. Root-Cause Diagnosis

**定义**：从表面症状追到最上游造成问题的结构变量。

**机制**：同一症状可能来自不同根因；修错层级会反复返工。

**诊断**：‘中段拖’是场景慢，还是主角没目标、对手不反制、Story Engine 已死？

**常见失败**：看到对白差就重写对白；看到节奏慢就删页数。

**修复**：沿 Premise→Engine→Agency→Causality→Structure→Scene→Dialogue 顺序定位第一个失效层。

## 116. Rewrite Priority

**定义**：按上游到下游安排修订，以减少无效返工。

**机制**：上游改动会重写下游条件，因此先修格式或台词通常浪费。

**诊断**：当前修改会不会因更高层决定改变而作废？

**常见失败**：第一轮就精修每句台词；结构重写后全部推翻。

**修复**：分 Pass：Premise/Engine→Agency/Causality→Character→Structure→Scene→Information→Dialogue→Continuity→Format。

## 117. Story Bible

**定义**：维护项目正典事实与状态的外部化记忆。

**机制**：长项目依赖大量跨集事实，单靠上下文记忆容易漂移。

**诊断**：人物年龄、伤势、物件、关系、秘密、世界规则是否可查？

**常见失败**：只有人物小传，没有动态状态；重写后旧设定混回。

**修复**：使用 LOCKED/ASSUMED/PROPOSED/REJECTED，并在每个单元完成后更新。

## 118. Knowledge State

**定义**：精确记录每个角色知道、误信、怀疑与隐藏的信息。

**机制**：对白、悬念、误会和策略都由知识状态决定。

**诊断**：角色当前行为是否依据他实际可得信息？

**常见失败**：角色读取作者视角；秘密明明暴露过却又当未知。

**修复**：为关键 Reveal 更新时间戳与来源，任何重写影响信息顺序时同步更新。

## 119. Master Scene Format

**定义**：以场景标题、动作、角色与对白为主体的可读提交稿结构。

**机制**：标准化元素让读者快速区分时空、行为与发言，也减少导演化噪音。

**诊断**：是否清晰区分 Scene Heading / Action / Character / Dialogue？

**常见失败**：大量镜头号、场号、剪辑指令和技术参数淹没故事。

**修复**：默认 submission/development draft 使用 master scenes，只有必要时写转场或特殊提示。

## 120. Final Readability

**定义**：终稿在因果、可演性、版面和语言上让读者无需猜测作者意图。

**机制**：剧本首先要被快速阅读与想象；清晰度是所有复杂技巧的交付层。

**诊断**：读者能否一遍读懂谁在哪、要什么、发生了什么、为什么重要？

**常见失败**：动作段过长；主语不清；心理叙述过多；格式花哨。

**修复**：短段落、明确主语、具体动作、删重复解释，并在终稿做纯可读性 pass。
