# Speculative Survival & Serial Logic Engine

## 目的

本文件用于以下高风险逻辑类型：

- 末世 / 灾难 / 生存
- 重生 / 回溯 / 预知
- 系统 / 空间 / 建造 / 升级
- 囤货 / 资源经营 / 基地建设
- 长线连载短剧 / 剧集
- 现实科学与虚构设定混合的故事

目标不是限制想象力，而是防止“爽点建立在明显逻辑漏洞上”。

核心原则：

~~~text
先建立现实因果
→ 再定义虚构突破
→ 给优势明确边界
→ 让成长制造新的阻力
→ 让代价持续生效
→ 把未解问题留给后续连载
~~~

---

## 1. 灾难必须有阶段

除非作品明确设定为“瞬时超自然灭世”，灾难不要一步到顶。

优先使用阶段链：

~~~text
异常预警
→ 基础设施失灵
→ 供应链与公共服务危机
→ 人类社会冲突
→ 生态异常
→ 虚构机制正式显现
→ 区域长期失守
→ 新秩序形成
~~~

每个阶段至少回答：

- 什么先坏？
- 普通人最先感受到什么？
- 哪些公共系统还能工作？
- 哪些资源最先紧缺？
- 人类如何误判或应对？
- 下一阶段由什么因果启动？
- 上一阶段留下什么持续后果？

禁止为了“快”让停电、停水、城市沉没、动物变异、全球秩序崩溃在同一天无因果同时发生。

---

## 2. 现实灾害与虚构突破必须分层

现实机制负责“让世界开始坏”。

虚构机制负责“让世界变成这部作品独有的世界”。

例如短期城市洪灾可以由：

- 极端降雨
- 风暴潮
- 高潮位
- 河流倒灌
- 排水系统失效
- 堤防受损
- 地面沉降
- 交通与电力设施进水

共同造成。

若剧情需要：

- 数日内全球永久海平面暴涨数十米
- 数周内普通动物自然进化成巨型怪物
- 普通疾病瞬间改变整个物种
- 城市一夜之间永久沉入深海

必须另有明确虚构原因，不要把明显超出现实尺度的事件直接归因于“气候变化”“海平面上升”或“动物适应”。

### 科学性检查

使用真实科学作为剧情依据时：

1. 区分短期事件与长期趋势。
2. 区分“已有科学事实”与“本作虚构推演”。
3. 不把相关性直接写成确定因果。
4. 需要具体数值或专业机制时优先核实可靠来源。
5. 可以夸张，但必须告诉自己夸张发生在哪个虚构节点。

---

## 3. 城市崩坏优先从功能停摆开始

现代城市不是“建筑还在 = 文明还在”。

灾难早期更有效的压力通常来自：

- 交通中断
- 港口 / 机场停运
- 配送停止
- 超市补货失败
- 燃油短缺
- 冷链失效
- 变电站 / 通信基站受损
- 自来水污染或停供
- 污水处理失效
- 医院超载
- 支付 / 银行 / 网络不稳定
- 官方避难点过载

先让“正常生活无法维持”，再让世界进入全面末日。

这也给主角的提前准备、物资判断和社会冲突留下戏剧空间。

---

## 4. 重生不是“换开场”，必须产生可兑现优势

重生、回溯、预知类故事必须回答：

- 主角到底知道哪些未来？
- 信息来源是什么？
- 哪些信息可以直接转化为资源、时间、位置或关系优势？
- 哪些只知道结果、不知道原因？
- 哪些完全不知道？

推荐三层知识：

### A. 高确定前期情报

主角亲历或可靠确认过，可用于快速崛起，例如：

- 灾难时间窗口
- 某交通线何时失效
- 某类物资何时暴涨
- 某地点会暂时安全 / 最终失守
- 某批设备会被遗弃
- 某人物在早期可靠或危险

### B. 结果已知、真相未知

例如：

- 知道某人会失踪，但不知道谁导致
- 知道避难所会毁灭，但不知道真正原因
- 知道某势力后来崛起，但不知道内部结构

这类信息制造警觉，不直接解决谜团。

### C. 完全未知

- 主角前世未经历的时间段
- 隐秘计划
- 系统来源
- 新时间线产生的人和事件
- 主角死亡后的世界

禁止让“重生”既没有实际价值，又在需要时突然变成全知。

---

## 5. 未来情报必须随时间线改变而衰减

重生优势最好有生命周期：

~~~text
早期：高度准确
→ 中期：出现偏差
→ 后期：只能参考
→ 新时间线：旧未来失去攻略价值
~~~

每次重大改变都应增加 Timeline Divergence。

可能的改变包括：

- 救下原本会死的人
- 提前拿走重要资源
- 让敌人提前行动
- 暴露不该暴露的信息
- 改变组织形成时间
- 改变关键关系

第一次“本应发生但没有发生 / 本不该发生却提前发生”的事件，应作为明确剧情节点。

之后主角必须逐渐从：

> 我知道答案

成长为：

> 我能在没有答案时做判断。

---

## 6. 维护 Future Knowledge Ledger

重生 / 预知项目至少维护：

~~~yaml
future_knowledge:
  event:
  source: personally_witnessed | reliably_confirmed | rumor | inferred
  original_time:
  original_location:
  known_fact:
  unknown_cause:
  confidence: high | medium | low
  actionable_value:
  has_protagonist_changed_dependencies: true | false
  current_reliability: valid | drifting | invalid
  last_checked_at:
~~~

角色不得使用自己未经历、未确认或已经失效的信息。

---

## 7. 战略能力默认应该隐藏

如果主角拥有：

- 系统
- 空间仓库
- 超能力
- 重生情报
- 特殊载具
- 稀缺技术
- 能改变权力结构的资源

默认先问：

> 暴露它对主角有什么收益？暴露后谁会盯上她？

如果没有必要收益，理性主角通常应该隐藏。

### 能力曝光阶梯

~~~text
完全隐藏
→ 有人发现结果异常
→ 有人怀疑主角藏有资源 / 技术
→ 小范围目击能力
→ 敌对势力确认能力存在
→ 能力成为战略争夺目标
→ 主角主动公开部分能力
~~~

第一次公开使用关键能力，应是剧情节点，有原因、有代价、有见证者、有下游后果。

禁止主角为了制造“震惊脸”在安全环境下无意义展示底牌。

---

## 8. 不要主动向未来敌人泄露未来

重生者知道某人未来会背叛自己时，最合理的第一反应通常不是：

> “三天后你会杀我。”

而是：

- 降低信任
- 切断资源权限
- 保持表面正常
- 观察对方行为
- 改变自己的可被利用条件
- 保护关键秘密
- 建立证据

主动说破未来会：

1. 暴露主角拥有异常信息。
2. 改变敌人的行为。
3. 降低未来情报可靠度。
4. 让观众误解主角掌握完整未来。

只有当“说破”本身是有意识的策略并且后果被写入剧情时才使用。

---

## 9. 资源、重量、体积和物流必须算进剧情

末世囤货和基地建设最容易出现生活逻辑硬伤。

每种关键资源至少考虑：

- 数量
- 重量
- 体积
- 价格
- 购买渠道
- 运输方式
- 储存位置
- 保质 / 维护
- 能源需求
- 消耗速度
- 谁知道它存在
- 谁能使用它

### 典型检查

普通购物车适合：

- 食品
- 药品
- 小工具
- 日用品
- 小型户外装备

大件设备通常需要：

- 平板车
- 托盘
- 叉车
- 货车
- 仓库配送
- 工业供应商

不要把大型发电机、储水罐、工业蓄电设备写成普通超市购物车随手带走，除非明确是便携型号。

大量饮用水本身非常重。

大型基地的难点不只是“有没有物资”，还包括：

- 怎么运
- 放哪里
- 怎么维护
- 怎么持续补充

---

## 10. 超自然仓储不能自动抹去物流剧情

即使主角有空间 / 系统仓库，也要定义：

- 初始容量
- 重量是否计入
- 是否能存活物
- 收取距离
- 是否需要所有权 / 接触
- 是否能在人前使用
- 是否耗能
- 是否可以瞬间释放
- 是否存在升级条件

推荐：

~~~text
正常采购 / 获得所有权
→ 正常运输至安全位置
→ 确认无人
→ 系统收纳
~~~

除非作品明确要做无约束神级外挂，否则不要让空间能力把所有采购、搬运、储存和安全问题全部删除。

---

## 11. 系统能力必须先有 Capability Ledger

系统故事禁止“剧情需要什么，就突然解锁什么”。

至少维护：

~~~yaml
capability:
  name:
  unlocked_at:
  source:
  input:
  output:
  limits:
  cooldown_or_cost:
  visibility:
  known_by:
  upgrade_path:
  cannot_do:
~~~

新能力只能来自：

- 已有规则自然升级
- 前面埋过的权限
- 完成明确条件
- 已建立的技术 / 材料组合

不能为了救场突然新增没有前置的能力。

---

## 12. 升级不能只靠“买东西刷经验”

资源经营型系统推荐：

~~~text
资源条件
+ 核心模块
+ 特殊材料 / 技术
+ 建设或任务条件
= 升级
~~~

升级必须同时产生至少一个新负担：

- 燃料消耗增加
- 维护成本增加
- 人员需求增加
- 暴露程度增加
- 航速 / 机动性权衡
- 新区域安全责任
- 更高价值吸引更强敌人

越大的基地，越不应等于“越来越轻松”。

---

## 13. 建立 Resource Ledger

长期生存项目至少跟踪：

~~~yaml
resource:
  name:
  category:
  amount:
  unit:
  storage_location:
  max_capacity:
  daily_consumption:
  resupply_source:
  owner_or_controller:
  known_by:
  critical_threshold:
  losses:
  last_updated_at:
~~~

关键资源包括但不限于：

- 淡水
- 食物
- 燃料
- 电力
- 药物
- 滤芯
- 维修件
- 船体材料
- 通信设备
- 人力
- 医疗能力
- 工程能力

不要让资源在场景间凭空恢复。

---

## 14. 主角成长必须自动制造新的敌意

“女主不断升级、所有人配合”会迅速失去戏剧张力。

推荐成长循环：

~~~text
获得优势
→ 被看见 / 被怀疑
→ 有人产生利益冲突
→ 对手试探
→ 对手调整策略
→ 主角付出真实代价
→ 保住部分成果 / 损失部分成果
→ 新成长
~~~

敌人出现必须与主角成长存在因果，而不是随机刷怪。

---

## 15. 使用 Opposition Ladder，而不是随机加坏人

推荐对手升级：

~~~text
亲属 / 熟人索取
→ 道德绑架 / 偷窃
→ 小型掠夺者
→ 有组织地方势力
→ 区域资源集团
→ 战略级组织
→ 系统性 / 世界级对抗力量
~~~

每一级对手应该：

- 因主角已有成果才关注她
- 拥有比上一层更强的资源 / 信息 / 组织能力
- 学习主角此前的做法
- 逼主角暴露新的弱点
- 带来不同类型的冲突，而不只是更多人持枪

### 小人与主反派要区分

“小人”可负责：

- 贪婪
- 嫉妒
- 亲情绑架
- 偷资源
- 泄密
- 勾结外人

长期核心对手则应有：

- 自己的世界观
- 独立战略
- 可持续资源
- 与主角理念冲突
- 能改变游戏规则的能力

不要让所有反派都是同一种坏。

---

## 16. 主角不能每次无损获胜

聪明主角可以预判，但不能永远“我早知道”。

每个中大型 Arc 至少考虑一次不可忽略的损失：

- 仓库被发现
- 备用燃料丢失
- 船体受损
- 安全点被迫放弃
- 重要盟友受伤 / 离开
- 信任下降
- 能力曝光
- 错误判断导致时间损失
- 升级材料被消耗在救人上

损失必须持续影响后续，不要下一集自动恢复。

---

## 17. 短剧的爽点应从“优势—阻碍—代价—兑现”产生

不要只有：

~~~text
获得系统
→ 升级
→ 再升级
→ 更大升级
~~~

更稳的短剧循环：

~~~text
目标
→ 主角利用优势行动
→ 对手 / 世界反制
→ 主角改变策略
→ 小胜或局部兑现
→ 付出代价
→ 新问题由本集结果启动
~~~

“总有人想害主角”不能写成纯随机迫害。

应让恶意来自：

- 资源稀缺
- 权力变化
- 秘密价值
- 嫉妒
- 既有关系
- 主角改变了他人的利益

---

## 18. 灾难升级不要等于“怪物越来越大”

长期连载可升级的维度包括：

- 资源压力
- 社会秩序
- 信息不确定
- 基地规模
- 组织政治
- 伦理代价
- 敌对势力
- 世界真相
- 地理范围
- 科技 / 生物规则
- 主角责任

推荐季级升级：

~~~text
第一阶段：活下来
第二阶段：建立稳定秩序
第三阶段：与其他秩序竞争
第四阶段：理解灾难真相
第五阶段：决定新文明应该是什么
~~~

不要只使用：

~~~text
鲨鱼
→ 巨鲨
→ 更大海兽
→ 超巨型海兽
~~~

## 19. 长期连载必须维护四层 Hook

### Episode Hook

本集兑现后自然产生的新问题。

### Arc Hook

5–10 集阶段目标解决后，改变故事规模或规则。

### Season Hook

本季核心问题得到回答，但留下更大的未解问题。

### Saga Hook

数季以后才能解释的世界核心谜团。

示例结构：

~~~yaml
hook:
  id:
  planted_at:
  surface_question:
  hidden_question:
  audience_knows:
  protagonist_knows:
  current_status: open | partial | paid | abandoned
  planned_payoff:
  payoff_horizon: episode | arc | season | multi_season
  dependency:
  risk_if_revealed_early:
~~~

不要在第一季同时解释：

- 系统来源
- 全部灾难真相
- 所有幕后组织
- 主角特殊性的最终原因
- 世界终极敌人

一季应该解决一个尺度的问题，同时打开下一个尺度。

---

## 20. 连载中的小角色可以升级为未来危险

早期小人物如果掌握：

- 主角囤货异常
- 主角预判过灾难
- 系统能力目击证据
- 关键基地位置
- 某段秘密关系

不要轻易用完即丢。

可使其：

- 逃亡
- 投靠更大势力
- 带着部分真相传播
- 在后续重新出现
- 成为某个大型势力理解主角的入口

这是角色伏笔复用，不是强行复活。

---

## 21. 关系弧不能用一次救人自动洗白

背叛、伤害、抢夺、欺骗等重大关系事件，需要债务持续存在。

关系修复优先使用：

~~~text
一次选择
→ 获得有限信用
→ 新压力测试
→ 第二次承担代价
→ 边界重新协商
→ 才可能改变关系定义
~~~

“救我一次”不等于“过去全部作废”。

---

## 22. 长项目必须扩展 Project State

生存 / 重生 / 系统 / 连载项目，在通用状态之外再维护：

~~~yaml
world_phase:
future_knowledge:
timeline_divergence:
resource_ledger:
capability_ledger:
secrecy_exposure:
opposition_ladder:
faction_interest:
open_hooks:
future_payoffs:
season_residue:
~~~

其中：

### world_phase

当前社会 / 灾难处于什么阶段，哪些基础设施还在运行。

### timeline_divergence

主角对旧时间线造成了哪些改变，哪些未来信息已失效。

### secrecy_exposure

谁知道主角有哪些能力，知道到什么程度。

### faction_interest

每个势力为什么注意主角、目前想得到什么、掌握多少证据。

## 23. Speculative Survival Script Doctor

出现末世、重生、系统、资源经营或长期连载时，正式定稿前额外检查：

### World Logic

- 灾难是否分阶段？
- 城市功能是否先于世界彻底毁灭？
- 现实科学与虚构突破是否区分？
- 每个阶段是否由上一阶段因果启动？

### Rebirth Logic

- 重生给了主角什么具体优势？
- 主角是否知道了自己不该知道的信息？
- 未来情报是否随着改变逐渐失效？
- 是否存在一次明确的“未来偏差”节点？

### Secrecy Logic

- 主角为什么公开 / 不公开能力？
- 首次暴露是否有必要性和代价？
- 谁知道多少？

### Resource Logic

- 大件物资如何购买、运输和储存？
- 水、燃料、药物和能源是否有实际消耗？
- 基地越大是否产生更大维护负担？
- 是否存在资源瞬移或无限恢复？

### System Logic

- 当前能力是否早已定义？
- 新能力是否有前置？
- 系统是否替作者解决了本应由人物解决的问题？
- 升级是否需要真实输入和代价？

### Opposition Logic

- 主角每次成长是否产生新的利益冲突？
- 对手是否学习并升级策略？
- 是否只是随机新增坏人？
- 主角是否经历真实且持续的损失？

### Serial Logic

- 本集钩子是否由本集结果产生？
- 本 Arc 是否解决了一个问题并放大下一个？
- 本季是否留有明确 Next Season Residue？
- 是否过早解释了所有世界谜团？

---

## 24. 高风险失败模式

禁止或重点警惕：

- 大型工业设备塞普通购物车却无型号解释
- 数吨物资塞进普通公寓却没有空间 / 仓库解释
- 主角在人前无必要展示战略外挂
- 重生者直接向未来背叛者报出未来剧情
- 重生者前期对未来几乎一无所知
- 重生者在需要时又突然知道所有秘密
- 未来被改变后情报仍 100% 准确
- 系统临时新增救场功能
- 买物资直接等于无限升级
- 基地扩大但消耗不增加
- 每次危机主角都无损获胜
- 随机加更强反派代替因果升级
- 灾难一天完成全部阶段
- 自然灾害无虚构原因直接制造极端快速生物进化
- 第一季把全部谜团、幕后和系统来源讲完
- 每季只靠更大的怪物升级规模

## 25. 最终原则

好的生存 / 重生 / 系统长线故事不是：

> 主角有外挂，所以一路赢。

而是：

> 主角先靠信息与准备获得优势；优势改变世界，引来觊觎和更强反制；旧答案逐渐失效；主角付出真实代价后，最终学会在没有攻略的未来建立自己的秩序。
