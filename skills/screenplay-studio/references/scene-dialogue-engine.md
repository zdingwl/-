# Scene & Dialogue Engine

## 场景是最小戏剧单元

一场戏至少存在：

~~~text
人物目标 → 阻力 → 策略 → 反制 → 转折 → 状态变化
~~~

## Scene Question

每场戏建立一个具体问题，例如“她能否让董事会相信自己？”问题越具体，场景越容易产生动作。

## Enter Late, Leave Early

晚进：尽量从冲突已启动处进入。
早出：核心转折与后果出现后及时离开。

不要自动写进门、寒暄、点菜、重复背景和刚才发生了什么。

## Tactic & Counter-Tactic

人物目标不变时，策略应该变化：

~~~text
请求 → 讨好 → 交换 → 威胁 → 揭秘 → 退出
~~~

对方也必须反制。没有策略变化的长对白容易变成信息宣读。

## Value Shift

场景前后至少改变一项：
- 安全 → 危险
- 信任 → 怀疑
- 上风 → 下风
- 隐瞒 → 暴露
- 联盟 → 决裂
- 追捕 → 被追捕
- 误解 → 新理解

## Turn

转折是导致旧策略失效的新事实或新行为：拒绝、证据、第三人、谎言被识破、越界、关系重定义、信息意义变化。

## Dialogue As Action

重要台词优先标成动作：
逼迫、诱导、安抚、隐瞒、试探、交换、羞辱、挑衅、求救、转移、拒绝、设局、争取。

如果只能标成“解释”，检查是否真的需要。

## Subtext

潜台词来自：

~~~text
表面说的 ≠ 真正想得到的
~~~

不是故意说得含糊。

## Exposition

信息最好进入冲突。避免人物互相朗读双方都知道的背景。

## Silence

沉默也必须有行动含义：拒绝、惩罚、害怕暴露、争控制、等待对方让步、无法回答。

## Action Lines

动作行优先短、具体、当前时态、可见、有因果。避免小说式心理墙。

## Scene Diagnostic

~~~text
谁想要什么？
谁阻止？
双方用了什么策略？
哪个瞬间改变场景？
场景前后什么不同？
造成什么后果？
删除它，下一场是否仍完全成立？
~~~

删除后毫无影响的场景通常只是说明。
