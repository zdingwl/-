# 场景、动作、对白与潜台词

本文件用于把已确定的结构真正写成可见、可听、可演的场景。

---

# 1. Scene Contract

每场内部至少确认：

```yaml
scene_contract:
  id:
  location:
  time:
  participants:
  viewpoint:
  entering_state:
  dramatic_question:
  main_goal:
  obstacle:
  tactic:
  counter_tactic:
  key_information:
  turn:
  value_shift:
  irreversible_consequence:
  exiting_state:
  next_scene_cause:
```

没有这些，不急着写对白。

---

# 2. 场景必须改变状态

常见 Value Shift：

- 信任 → 怀疑
- 优势 → 劣势
- 安全 → 危险
- 隐藏 → 暴露
- 希望 → 绝望
- 拒绝 → 动摇
- 猎人 → 猎物
- 联盟 → 分裂
- 无知 → 知道
- 掌控 → 失控

如果一场前后完全一样，优先删、并或重写。

---

# 3. 晚进早出

可以省略：

- 进门
- 坐下
- 点餐
- 寒暄
- 走廊移动
- 等电梯
- “谢谢你来”
- 冲突后重复总结

进入真正改变局势的位置。

---

# 4. Action / Reaction / Counter

平面对话：

```text
甲说观点
乙说观点
甲重复观点
乙重复观点
```

戏剧对话：

```text
甲行动
→ 乙反应
→ 甲施压
→ 乙换策略
→ 新信息
→ 甲重新判断
→ 转折
```

---

# 5. 目标不是情绪

差：

> 这场她很愤怒。

好：

> 她要逼丈夫承认钱去了哪里。

情绪来自行动过程。

---

# 6. 阻碍必须具体

阻碍可能是：

- 对方拒绝
- 对方拥有更强筹码
- 时间不足
- 第三人在场
- 身份限制
- 法律制度
- 物理限制
- 自己不敢承担代价
- 公开与私下目标冲突

---

# 7. 策略变化

一个场景至少允许人物调整方法。

例：

```text
请求
→ 解释
→ 交换
→ 威胁
→ 放弃谈判直接行动
```

持续重复同一种策略会让场景静止。

---

# 8. 场景转折

Turn 不是“突然发生一件事”。

它应改变：

- 谁占上风
- 人物下一步策略
- 当前问题答案
- 关系位置
- 风险
- 信息
- 资源

---

# 9. 对白是一种行动

每句重要台词问：

> 说这句话，是为了让对方发生什么变化？

常见功能：

- 试探
- 诱导
- 逼供
- 隐瞒
- 挑衅
- 拒绝
- 讨价还价
- 改变定义
- 争夺道德高地
- 安抚
- 施压
- 转移
- 终止关系
- 建立同盟

---

# 10. 三层对白

强对白常有：

```text
表面说了什么
↓
真正想让对方做什么
↓
自己都不愿承认的深层需求
```

不要把三层都说出来。

---

# 11. 信息进入冲突

差：

> 你知道父亲十年前去世后，叔叔接管了公司。

好：

> 你爸死后，是谁让公司没倒？

> 你只是坐上了他的椅子。

信息成为筹码。

---

# 12. 人物声音

```yaml
voice_fingerprint:
  sentence_length:
  vocabulary:
  formality:
  directness:
  metaphor_use:
  humor:
  avoidance:
  anger_pattern:
  lying_pattern:
  intimacy_pattern:
  professional_language:
  repeated_phrases:
  forbidden_words:
  never_says_directly:
```

测试：

> 去掉人物名，是否仍能大致判断是谁在说？

---

# 13. 自然度

允许：

- 半句话
- 打断
- 不回答
- 改口
- 重复关键词
- 沉默
- 误听
- 避开问题
- 只回答一半

不要让每个人都像正式辩论。

---

# 14. 沉默

沉默也必须有行动意义。

例：

- 不接对方递来的东西
- 把椅子移远
- 删除未发送信息
- 把门留着而不是关上
- 不替对方解释

---

# 15. 视觉叙事

优先用：

- 距离
- 位置
- 物件
- 门
- 桌子
- 衣物
- 手机
- 钱
- 文件
- 食物
- 伤口
- 谁坐 / 谁站
- 谁先走

承载权力和关系。

---

# 16. Sound-off Test

关掉声音后，观众至少应该能大致理解：

- 谁想控制局面
- 谁正在失去优势
- 谁亲近 / 疏远
- 是否发生重要变化

不是要求无对白也能理解全部情节。

---

# 17. 动作描写

动作：

- 简短
- 可见
- 可执行
- 当前发生
- 一段一个主要动作
- 不替演员解释心理

差：

> 她愤怒、受伤又绝望地看着他。

好：

> 她摘下戒指。

> 没有还给他。

> 她放进自己的口袋。

---

# 18. 场景双重功能

优先让场景同时做两件以上：

- 推剧情 + 改关系
- 给信息 + 造误判
- 回收伏笔 + 失去资源
- 展示人物 + 触发下一步
- 建立爱情 + 提高外部代价

但不要强塞无关功能。

---

# 19. 场景删除测试

删掉后问：

- 主线是否受损？
- 人物弧是否受损？
- 关系是否受损？
- 信息是否断裂？
- Setup / Payoff 是否断裂？
- 下一场是否无原因发生？

全部“不” → 删除或合并。

---

# 20. 场景压缩

常见可压缩：

- 两场相同目的谈话
- 两个相同信息传递者
- 重复争吵
- 重复情绪反应
- 过程动作
- 已经被画面说明的对白

---

# 21. 对白二次 Pass

结构锁定后：

```text
□ 这句话有行动目的吗？
□ 有潜台词吗？
□ 重复画面了吗？
□ 重复上一句了吗？
□ 符合人物声音吗？
□ 太书面吗？
□ 太完整吗？
□ 能用动作代替吗？
□ 是否在解释双方都知道的事？
□ 是否把主题直接说出来？
```

---

# 22. 去 AI 腔

警惕：

- “然而”
- “与此同时”
- “他意识到”
- “命运的齿轮”
- “一切才刚刚开始”
- 每个角色都爱总结
- 每个人逻辑都过度完整
- 情绪形容词堆叠
- 每场都先写气氛再说事
- 每场都用一句神秘台词收尾

---

# 23. 剧本格式最低规范

推荐中文格式：

```text
场次 12
内景｜医院走廊｜夜

林乔站在缴费机前。

屏幕上：余额不足。

她重新插卡。

还是一样。

身后，父亲的主治医生停下。

医生
你姐姐还没来？

林乔拔出卡。

林乔
她不会来了。
```

保持：

- 场次
- 内/外景
- 地点
- 时间
- 可见动作
- 人物
- 对白

不要自动加入镜头术语。

---

# 24. 场景完成检查

```text
□ 有目标
□ 有阻碍
□ 有策略
□ 有反制
□ 有变化
□ 有后果
□ 有视觉信息
□ 对白不是说明书
□ 场景结束后下一步更明确
```
