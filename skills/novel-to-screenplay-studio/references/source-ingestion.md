# 长篇源素材读取与索引

适用于长篇小说、百万字网文、多文件 IP、系列小说和跨卷素材。

核心原则：

> 先建立可检索的全局模型，再做改编判断；不要一边读前文一边直接正式改写。

---

# 1. 三层读取

## 第一层：目录扫描

先获得：

- 文件
- 卷
- 章节
- 章节顺序
- 可用元数据

目标：知道“素材有多大、结构在哪里”。

## 第二层：功能索引

每章 / 每段只提取：

- POV
- 剧中时间
- 出场人物
- 重大事件
- 人物选择
- 后果
- 关系变化
- 新信息
- 秘密状态
- Setup / Payoff
- 情绪价值

写入 Source Index。

## 第三层：关键段深读

根据索引二次深读：

- 触发事件
- 关键关系转折
- 中段
- 重大 Reveal
- 高潮
- 结局
- 人物弧证明
- 反复出现的意象与物件

---

# 2. Chunk 不是故事单元

分块读取只是上下文管理。

禁止：

- 每块单独总结后直接拼接
- 每读一块就锁一个影视集
- 忘记后文对前文的重新解释
- 把章节标题误当戏剧功能

每完成一个 Chunk，只更新全局状态。

---

# 3. 增量合并

每块结束执行：

```text
新事实
→ 与旧正典去重
→ 检查冲突
→ 更新时间线
→ 更新人物状态
→ 更新秘密
→ 更新 Setup / Payoff
→ 标记待后文验证的假设
```

待验证内容只能是 ASSUMED，不能 LOCKED。

---

# 4. 人物关系自动抽取原则

每次两名角色发生重要互动时记录：

```yaml
interaction:
  a:
  b:
  event:
  a_goal:
  b_goal:
  power_before:
  power_after:
  trust_before:
  trust_after:
  new_dependency:
  new_conflict:
  secret_involved:
```

最终从互动事件生成 Relationship Map。

不要根据“亲属 / 同事 / 情侣”标签直接推断关系状态。

---

# 5. 全局收敛条件

满足以下条件后，才进入正式 Adaptation Design：

```text
□ 主线因果已可追踪
□ 主要角色功能已知
□ 结局已读取
□ 核心秘密及揭露顺序已知
□ 时间线无重大空白
□ 关键 Setup / Payoff 已索引
□ 后文是否推翻前文认知已检查
□ 核心情绪承诺可说明
```

否则继续读源素材。
