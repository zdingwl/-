# Example Project：原创悬疑电影

## 用户输入

```text
一个失忆律师发现，
自己曾经替真正的凶手赢下无罪判决。

写成完整悬疑电影。
```

---

## 1. 路由

```yaml
entry_mode: original
target_medium: feature
genre: mystery / legal thriller
```

---

## 2. Premise

```text
一名因事故失去部分记忆的刑辩律师，
发现自己最著名的胜诉案可能替真正的凶手洗清罪名。
为了查明自己当年到底知道多少，
他必须重新调查一个会毁掉事业、自由与自我认知的旧案。
```

---

## 3. 主角

```yaml
external_goal: 查明旧案真相
internal_need: 承认“赢”不能代替“正确”
misbelief: 只要程序合法，律师无需承担真相责任
fear: 发现自己当年不是被骗，而是主动忽略证据
strength: 极强的交叉询问与证据逻辑
flaw: 把道德问题转化成技术问题
final_choice: 公开一份会证明自己职业失德、但能推翻旧案的证据
```

---

## 4. 对抗力量

不是简单“凶手追杀”。

可以同时包含：

- 真凶
- 当年的事务所合伙人
- 法律时效 / 证据规则
- 主角过去的自己留下的决定
- 被害人家属对他的敌意

---

## 5. Story Spine

```text
旧平衡：失忆后回归工作
→ 触发：收到一段自己当年录下却不记得的语音
→ 选择：秘密重查旧案
→ 新局面：发现当年证据并非单纯失误
→ 中段：确认自己曾主动压下一条线索
→ 代价：事务所和家属同时对他施压
→ 低谷：新证据似乎证明他当年收过利益
→ 反转：利益记录是伪造，但他确实做过另一个更严重的选择
→ 高潮：公开证据将毁掉自己，却能让真正案件重启
→ 结局：他失去职业地位，但第一次主动承担“知道真相之后”的责任
```

---

## 6. 场景原则

法庭戏不能只是“精彩辩论”。

每场必须改变：

- 证据意义
- 人物立场
- 主角自我认识
- 权力
- 风险

---

## 7. Dialogue Pass

主角早期语言：

- 技术化
- 准确
- 回避情绪
- 喜欢定义术语

后期：

- 仍然克制
- 但不再用程序词汇逃避责任

人物弧因此进入语言层，但不靠演讲完成。
