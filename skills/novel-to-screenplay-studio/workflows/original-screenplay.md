# Workflow：原创想法 → 完整剧本

---

# Stage 0：识别输入

用户可能只提供：

- 一句话
- 一个角色
- 一个世界规则
- 一个冲突
- 一个主题
- 一个结局

不要要求用户补完所有表格。

从现有信息继续构建。

---

# Stage 1：Concept → Premise

明确：

- 主角
- 异常变量
- 外在目标
- 对抗
- Stakes
- 戏剧问题

Gate：

> 如果只有题材，没有可行动的问题，先形成 Premise。

---

# Stage 2：类型承诺

明确主要体验：

- 爱情
- 悬疑
- 惊悚
- 喜剧
- 高爽
- 人物剧
- 混合类型

不要让后续结构把类型冲淡。

---

# Stage 3：主角

建立：

- Want
- Need
- Misbelief
- Fear
- Contradiction
- Resource
- Secret
- Final Choice

主角必须能行动。

---

# Stage 4：对抗

对手 / 阻力必须：

- 有自己的目标
- 有资源
- 有策略
- 会适应
- 能制造升级

---

# Stage 5：核心关系

建立：

- 互相想要什么
- 为什么需要对方
- 为什么又互相阻碍
- 权力如何变化
- 最终关系状态

---

# Stage 6：结局先行

先决定：

- 外部问题最终怎样回答
- 核心关系最终怎样
- 主角最后做什么选择
- 最后一幕 / 最后画面

反推必要 Setup。

---

# Stage 7：Story Spine

建立宏观因果。

要求重大节点不是随机事件，而是前面选择的后果。

---

# Stage 8：媒介适配

加载：

`references/medium-profiles.md`

把 Story Spine 转成：

- 电影段落
- Season / Episode
- 短剧 Episode
- 动画结构

---

# Stage 9：Beat Sheet

每个 Beat 必须写具体：

- 发生什么
- 谁做
- 为什么
- 结果是什么
- 状态怎么变

不要用抽象占位词。

---

# Stage 10：Scene List

每场必须知道：

- 为什么存在
- 谁想得到什么
- 谁阻止
- 如何反制
- 场景如何转折
- 为什么必须发生下一场

---

# Stage 11：First Draft

第一遍优先：

- 完成故事
- 保证因果
- 保证人物行动
- 保证场景变化
- 保证结局

不要过早追求金句。

---

# Stage 12：状态更新

长项目建立：

- Story Bible
- Knowledge State
- Secret Ledger
- Setup / Payoff
- Handoff

---

# Stage 13：Revision

按层级：

1. Premise
2. 类型承诺
3. 主角主动性
4. 因果
5. 人物与关系
6. 结构
7. 场景
8. Reveal
9. Dialogue
10. Visual
11. Continuity
12. Compression
13. Anti-AI

---

# Stage 14：Final

用户要完整剧本时，最终不能停在大纲。

必须进入：

```text
场次
+
动作
+
人物行为
+
对白
+
转折
```
