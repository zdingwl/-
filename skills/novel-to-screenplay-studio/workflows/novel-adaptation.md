# Workflow：小说 / IP → 剧本

这是执行顺序，不是知识百科。

---

# Stage 0：恢复项目

如果是继续项目：

读取：

1. Project State
2. LOCKED
3. Decision Log
4. Handoff
5. Knowledge State
6. Adaptation Ledger
7. Open Setup / Payoff

确认：

- 写到哪里
- 哪些不能改
- 这次用户要什么

然后从当前阶段继续。

---

# Stage 1：读取素材

如果素材短：

完整读取。

如果素材长：

按章节 / 卷 / 文件建立索引，再分块读取。

提取：

- 人物
- 事件
- 因果
- 关系
- 时间线
- 世界规则
- 秘密
- Setup / Payoff
- 情绪高点
- 标志性元素

不要边读边正式改写。

---

# Stage 2：Story DNA

输出或内部锁定：

- Logline
- 主角目标
- 内在需求
- 错误信念
- 戏剧问题
- 主题问题
- 对抗
- 核心关系
- Stakes
- 情绪承诺
- 结局

Gate：

> 如果说不清“原作真正的主戏是什么”，不要进入分集或场景。

---

# Stage 3：目标媒介

确定：

- 电影
- 剧集
- 短剧
- 动画

加载：

`references/medium-profiles.md`

判断原作体量是否适配。

如果不适配，给出最小必要说明并选择合理方案，不要停住整个任务。

---

# Stage 4：改编尺度

内部选择：

- 高忠实
- 功能忠实
- 自由改编

根据用户要求和素材决定。

建立：

`Adaptation Matrix`

---

# Stage 5：处理不可影视化内容

逐类处理：

- 内心独白
- 作者说明
- 回忆
- 世界观
- 抽象情绪
- 长时间跳跃
- 多 POV

转成：

- 选择
- 行为
- 物件
- 空间
- 冲突
- 关系策略
- Reveal
- 后果

---

# Stage 6：人物与支线重构

检查：

- 功能重复人物
- 重复竞争者
- 一次性递消息角色
- 无独立功能支线
- 只靠篇幅存在的日常

决定：

- KEEP
- MERGE
- CUT
- TRANSFORM

更新因果。

---

# Stage 7：信息与时间重排

建立：

- POV Map
- Reveal Ledger
- Timeline
- Knowledge State

目标：

> 让观众在正确的时间知道正确的东西。

---

# Stage 8：影视版结构

先重建完整因果：

```text
旧平衡
→ 触发
→ 主角选择
→ 新局面
→ 升级
→ 中段变化
→ 代价
→ 低谷
→ 最终策略
→ 高潮
→ 结局
```

剧集再拆 Episode。

短剧再做单集微结构。

禁止按原作章节直接切。

---

# Stage 9：Beat / Episode Map

每个单元检查：

- 有明确目标吗？
- 有动作吗？
- 有阻力吗？
- 有变化吗？
- 有回报吗？
- 有后果吗？
- 与下一单元有因果吗？

---

# Stage 10：Scene Map

将每个 Beat 变成可写场景。

每场记录：

- Source Origin
- Adaptation Decision
- Scene Contract
- Visible Externalization

Gate：

> 如果一场只能写成“人物回忆 / 解释”，继续影视化。

---

# Stage 11：正式剧本

逐场：

- 场次标题
- 可见动作
- 人物行为
- 完整对白
- 场景转折

不要混入：

- 镜头
- 焦段
- 生图提示
- 视频提示

---

# Stage 12：每单元更新状态

更新：

- Handoff
- Knowledge
- Secrets
- Objects
- Relationships
- Setup / Payoff
- Adaptation Ledger

---

# Stage 13：Script Doctor

读取：

`references/revision-quality-gates.md`

顺序：

1. Adaptation Integrity
2. Premise / 主角
3. 因果
4. 人物 / 关系
5. 结构
6. 场景
7. 信息
8. 对白
9. 连续性

---

# Stage 14：Final

最终判断：

```text
原作核心还在
+
影视版独立成立
+
目标媒介适配
+
剧本可见可演
+
连续性可靠
```
