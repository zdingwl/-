# 回归测试说明

Skill 大版本升级时使用。

目标：

> 判断新版是否真的写得更好，而不是文件更长。

---

# 测试方法

```text
固定同一输入
→ 旧版生成
→ 新版生成
→ 隐藏版本标签
→ 按统一 Rubric 评分
→ 记录根问题
→ 判断是否升级
```

---

# 必测维度

- 改编完整性
- Story DNA
- 主角主动性
- 因果
- 人物与关系
- 媒介适配
- 结构
- 场景
- 对白
- 信息控制
- 连续性
- 非模板化

---

# 防止过拟合

至少保留两个隐藏案例。

隐藏案例不能参与日常调规则。

大版本只在最终验收时使用。

---

# 失败信号

新版出现以下情况时，即使某些评分提高也不能直接升级：

- 所有故事越来越像同一种模板
- 电影被写成短剧
- 慢燃被强制高频反转
- 改编项目丢失原作核心
- 为了忠实原作导致剧本不可演
- 人物知识状态变差
- 规则大量显性出现在正文


## Writer's Room 专项回归

运行：

`review-pass-cases.md`

重点检查：

- 上游 P0 是否阻断无意义的下游精修
- Reviewer 是否提供具体证据和根因
- Reviewer 是否越权直接改正典
- 多 Review 冲突是否进入 Executive Review
- Rewrite 后是否重跑正确的依赖 Pass
